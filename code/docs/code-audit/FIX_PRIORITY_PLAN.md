# 修复优先级计划

本计划只给出顺序，本轮不执行修复。

## P0（阻断发布）

1. 订单留言对象权限：给 `sendOrderMessage/listOrderMessages` 增加订单参与人校验，并补 WORKER A 访问 WORKER B 订单的反向测试。
2. 报表品牌隔离：四类报表统一接收品牌上下文，在数据库查询与结果层双重过滤；补 BRAND_ADMIN、FINANCE_REVIEWER 跨品牌反向测试。

验收标准：相关越权请求返回 `FORBIDDEN/无权`；平台管理员 `*` 范围不受误伤；`npm test` 全绿。

## P1（业务正确性）

1. 配置贯通：让支付时限、抢单池超时、指派超时、最大进行中订单、周提现次数、起提金额均由 `configs` 生效；订单创建/入池/指派时写配置快照。
2. 定时任务部署：为 `timeoutCloseUnpaidOrders`、`timeoutMarkPool`、`timeoutRejectAssignments` 配置并记录 uniCloud 定时触发器；补一键核验脚本。
3. 管理后台角色口径：按测试基线只允许 ADMIN，或先修改并签署业务测试基线；未经确认不得以现有扩展角色覆盖测试要求。
4. 员工管理补齐：新增 CS 创建入口，实名通过/驳回双向操作，统一初始密码和首次改密状态。
5. 红线统一：将红线词表移入共享模块，前后端同源生成；补测试文档全部词语的服务端拒绝测试。
6. 字典/VIP：增加停用、受引用禁止删除；修正 VIP 删除参数为 `vipId`，补重复添加/删除回归。
7. 唯一索引：为订单号、支付流水、退款号、品牌 code/AppID、VIP 匹配键、幂等键建立云数据库唯一索引并验证冲突行为。

验收标准：TC05、TC13、TC23、TC27、TC30～TC34、TC40 的代码结论可提升，配置刷新后真实生效。

## P2（演示与人工验收）

1. 支付成功页新增携订单号的客服入口。
2. 客服待办改用后端 `dashboard` 固定口径，覆盖提现七态和退款待审批子状态。
3. Worker 首页从后端返回最大接单数，增加新单角标并校验声音策略。
4. 修正密码规则提示为 12 位强密码，并在改密成功后明确重新登录。
5. 对 `getProduct` 增加上架状态校验。
