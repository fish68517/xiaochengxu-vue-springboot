# 项目可交付成熟度摘要

## 结论

当前项目不是“功能缺失型原型”，而是“生产链路已铺开、仍有安全与验收缺口的候选版本”。42 个测试项均能定位到生产代码，但严格满足测试文档的仅 15 项（35.7%）。在关闭 2 个 P0 安全问题、修正 8 组 P1 问题并完成真实环境验收前，不建议商业放量。

## 已具备的核心能力

- 三端应用结构完整：客户、客服/接单工作台、管理后台分别构建。
- 生产后端 `game-service` 有统一 action 路由、会话鉴权、角色矩阵和数据库仓储。
- 订单 12 状态、退款子状态、提现状态及主要异常路径已编码。
- 抢单、结单入账、提现冻结/解冻、退款追佣等关键写操作使用事务或条件更新。
- 阿里云与腾讯云 `game-service` 核心文件哈希一致；领域导出同步检查通过。
- 42 份阿里云 schema 均为客户端拒绝直连读写。
- 当前 `npm test` 共 192 项全部通过；这些是自动化代码证据，不替代微信、云端和真机验收。

## 当前不能商用放量的原因

1. 订单留言只做品牌校验，没有校验接单人员是否为该订单参与人，存在跨订单读取/发言风险。
2. 报表服务读取全量集合，没有按调用者 `brandScopes` 过滤，品牌管理员/财务角色存在跨品牌数据泄露风险。
3. 支付、退款、订阅消息仍需微信真实商户、服务号、小程序配置及回调验收；近期云函数还出现过资源耗尽，不能据静态代码宣称可用。
4. `system-runner` 代码存在，但仓库内没有可证明已经部署的定时触发器配置。
5. 多个后台配置仅能保存，业务执行仍采用常量，造成“配置看似成功、运行不生效”。
6. 数据 schema 未见唯一索引定义文件，订单号、支付流水、幂等键等唯一性需要在云控制台补齐并留证。

## 建议发布门槛

- P0 清零：修复 TC22、TC38，并增加跨订单/跨品牌回归测试。
- P1 清零或有书面豁免：超时配置、角色口径、员工管理、红线、字典/VIP、索引。
- 微信真实环境完成 JSAPI、MWEB、支付回调、退款回调、订阅消息闭环。
- 定时触发器完成部署并用缩短时限验证 E1、TC13、TC27。
- 手机微信、Safari、Chrome 及电脑 Chrome、Edge 完成 42 项人工回归，保存视频/截图/日志。
- 云函数配额与告警验证通过，发布窗口内没有 `PrePayResourceExhausted`。

## 审计边界

本轮只读源码、schema 和自动化测试，没有修改业务源码，没有调用真实微信接口，也没有把本地 Memory DB 结果当作生产通过。
