## 三、构建与部署步骤

> 顺序：domain 单一源构建 → 全量测试 → 四套前端构建 → 云函数 + schema 部署 → 前端托管 / 小程序上传 → 微信后台配置。

1. **领域单一源构建与校验**
   - `node scripts/build-domain.mjs`：将 `packages/domain/src/index.js` 打包为 CommonJS，输出 `uniCloud-tcb/cloudfunctions/game-service/lib/domain.cjs`（勿手改）。
   - `node scripts/verify-domain-sync.mjs`：重新构建后比对 `domain.cjs` 与 `packages/domain` 的导出集合与抽样行为一致性。

2. **全量测试**
   - `npm test`（或 `node scripts/verify-all.mjs` 一键跑测试 + e2e-smoke 并落盘证据）。当前 196 例全绿。

3. **四套前端构建（各 app 目录内执行）**
   - client：`npm run build:h5`（→ `apps/client/dist/build/h5`）、`npm run build:mp-weixin`（→ `apps/client/dist/build/mp-weixin`）
   - workbench：`npm run build:h5`（→ `apps/workbench/dist/build/h5`）
   - admin：`npm run build:h5`（→ `apps/admin/dist/build/h5`）

4. **云函数 + schema 部署**
   - `node scripts/deploy-unicloud.mjs`：先构建 domain.cjs，再经 HBuilderX CLI 上传 `game-service`、`wechat-callback` 及全部 schema（`uniCloud-tcb/database/*.schema.json`）。
   - 部署后需在 uniCloud 控制台手动完成 URL 化（CLI 不支持）：`game-service` 开 URL 化并配置 `/pay-notify`（微信支付回调）、`wechat-callback` 开 URL 化并配置微信消息推送。

5. **前端托管（双域）/ 小程序上传**
   - 客户域（web-view H5 下单/浏览，仅 client）：`node scripts/deploy-hosting.mjs client`（上传 apps/client H5，前缀 `/`，空间 `HOSTING_CLIENT_SPACE`）。
   - 后台域（客服 + 接单 + 管理同域）：`node scripts/deploy-hosting.mjs backend`（上传 workbench → `/workbench/`、admin → `/admin/`，空间 `HOSTING_BACKEND_SPACE`）。
   - 两个域名分别在 uniCloud 控制台绑定到对应空间；发布后跑 `node scripts/verify-hosting.mjs` 健康检查（env `HOSTING_CLIENT_URL`/`HOSTING_BACKEND_URL`）。
   - 小程序：微信开发者工具导入 `apps/client/dist/build/mp-weixin`，上传审核发布（各品牌 AppID 分别上传同一产物）。

6. **微信后台配置清单**
   - 小程序：认证、备案、类目与资质审核；web-view 业务域名 + 校验文件；订阅消息模板选用（一次性「订单状态更新」）。
   - 认证服务号：网页授权域名（JS 安全域名，snsapi_base 网页授权）。
   - 微信支付商户号：关联服务号（JSAPI 对商户支付前置）；H5 支付（mweb）场景开通；回调地址配置（`WECHAT_PAY_NOTIFY_URL`，即 URL 化 `/pay-notify`）。
   - 微信客服：消息推送 URL 配置（`WECHAT_MP_KF_TOKEN` 验签）。
   - 商家转账到零钱（二期；一期为人工打款，预留接口）——如开通需「佣金报酬」场景报备。

7. **初始数据配置（首次部署后）**
   - 管理端「品牌配置」创建默认品牌并置 isDefault=true（保证未知 appId 回退到主品牌而非首个 ON 品牌，见《可拓展性评估》§4）；
   - 初始管理员/客服账号、初始商品与字典、各品牌文案红线复核。
