# 环境与责任矩阵

| 项目 | development | staging | production |
|---|---|---|---|
| API_MODE | local | unicloud | unicloud |
| VITE_APP_ENV | development | staging | production |
| VITE_API_MODE | local | unicloud | unicloud |
| VITE_BRAND_CODE | 与 BRAND_CODE 一致 | 与 BRAND_CODE 一致 | 与 BRAND_CODE 一致且进入生产白名单 |
| PAYMENT_MODE | mock | wechat | wechat |
| MESSAGE_MODE | mock | wechat | wechat |
| 数据 | 演示数据 | 脱敏测试数据 | 真实业务数据 |
| 品牌 | demo-a/demo-b | 测试品牌 | 生产白名单品牌 |
| Secret | 本机临时值 | staging Secret | production 独立 Secret |
| 发布 | 开发者本地 | CI + 测试批准 | CI 产物 + 多方批准 |
| 备份 | 本地演练 | 真实恢复演练 | 自动备份 + 异地副本 |

## 职责分离

- 技术负责人：架构、云部署、系统密钥和回滚；
- 发布管理员：生产发布审批和版本冻结；
- 财务负责人：商户号、退款、提现和对账；
- 法务/业务负责人：协议、隐私、主体和业务规则；
- 测试负责人：staging 真实链路和负向测试证据。

单一人员不得同时掌握生产数据库写权限、支付 Secret 管理权限和发布最终审批权。

staging/production 构建时，`VITE_API_BASE` 必须留空，由前端走 `uniCloud.callFunction`；发布门禁同时校验前后端环境、API 模式和品牌编码一致，防止构建产物串环境或串品牌。
