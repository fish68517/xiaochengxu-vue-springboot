# 第三阶段发布与回滚清单

## 环境边界

| 环境 | API_MODE | PAYMENT_MODE | MESSAGE_MODE | 数据与密钥 |
|---|---|---|---|---|
| development | local | mock | mock | 本地内存数据，不读取生产商户配置 |
| staging | unicloud | wechat | wechat | 测试云空间、测试品牌、Secret 管理 |
| production | unicloud | wechat | wechat | 生产云空间、生产品牌、Secret 管理；必须有备份和回滚包 |

变量键见根目录 `.env.example`。该示例只描述合同，不能作为真实 Secret 文件提交。

## 发布前

1. 运行 `npm run verify:all`，确认 lint、domain、测试、四套构建、API/UI 冒烟全部通过；
2. 运行 `npm run verify:brand-matrix`，确认品牌 code、AppID、渠道唯一；需要重建演示品牌时运行 `npm run build:brand-matrix`；
3. staging/production 执行 `npm run release:preflight -- --environment staging|production`；
4. 从真实数据库导出完整备份，生成集合数量、记录数和 SHA-256 manifest；
5. 在隔离目录/测试空间执行 `npm run restore:drill -- --dir <备份目录>`；
6. 生成 `npm run rollback:bundle -- --backup-dir <备份目录>`，把输出路径写入 `ROLLBACK_BUNDLE_PATH`；
7. production 完成 `docs/commercial/商业决策记录.md` 审批，设置 `COMMERCIAL_DECISIONS_APPROVED=true`、`BRAND_ENTITY_MODE`、`PRODUCTION_BRAND_CODES`、`DEMO_DATA_ENABLED=false`；
8. production 设置 `RELEASE_APPROVED=true`、`DB_BACKUP_ID`、`ROLLBACK_BUNDLE_PATH`，再次运行门禁；
9. 核对小程序 AppID、业务域名、网页授权域名、支付商户绑定、支付/退款回调、客服回调、订阅模板和品牌素材；
10. 核对 `INTERNAL_SECRET` 与 `SCHEDULER_SECRET` 独立，`system-runner` 未开启 URL 化，三个定时任务由控制台触发器调用。

## staging 验收证据

- A/B 品牌分别登录、商品读取、下单与订单查询；
- A 员工读取 B 数据返回 403/404；
- 1 分钱 JSAPI/MWEB 支付、重复回调、错误金额回调不推进订单；
- 1 分钱退款、追佣反向流水、钱包账本重算一致；
- 两个接单账号并发抢单仅一个成功；
- 提现审批、出款失败、重试和打款凭证；
- 异议追加证据、审理、退款型裁决与结案；
- 管理端真实落库、审计 before/after、健康检查截图和原始 JSON。

证据必须区分“本地/Mock”和“真实 staging”，不能用 HTTP 200 或本地构建代替真实支付、真实云空间和微信开发者工具验收。

## 回滚顺序

1. 暂停下单、退款、出款等写入口；
2. 切回上一版本静态托管和云函数；
3. 校验备份 manifest 与 SHA-256；
4. 在隔离空间执行恢复演练和钱包账本对账；
5. 经业务、技术和财务负责人共同批准后，才允许恢复生产数据；
6. 恢复入口后执行品牌启动、鉴权、订单查询、支付回调和后台健康检查。

脚本不会自动覆盖生产数据库。真实恢复必须由云平台备份能力执行，并保留操作者、时间、备份 ID 和审批记录。
