# 萌宠生活商城小程序：腾讯云最小部署流程

> 适用项目：`E:\bishe27\wxMiniProgram`  
> 目标环境：腾讯云 Windows 轻量应用服务器 / Windows 云服务器  
> 当前服务器界面判断：例图中终端是 Windows PowerShell，文件路径是 `C:\...`，因此本文按 **Windows Server** 编写。  
> 编写日期：2026-08-21

## 1. 先理解“部署”到底在做什么

这个项目上线时不是把整个项目原样放进微信，也不是让小程序直接连接 MySQL。各部分的去向如下：

```text
本地电脑
├─ uni-app 小程序源码 ──构建──> 微信小程序产物 ──上传──> 微信平台
├─ FastAPI 后端源码 ───打包/上传────────────────────> 腾讯云服务器
├─ Element Plus 后台 ──构建──> 静态文件 ───────────> 腾讯云服务器 Nginx
└─ 本机 MySQL ─────────导出 SQL/上传/导入───────────> 腾讯云服务器 MySQL

微信用户
    ↓
微信小程序
    ↓ HTTPS
https://api.example.com/api/v1
    ↓ Nginx 反向代理
FastAPI（只监听 127.0.0.1:8000）
    ↓
MySQL（只允许服务器本机连接）
```

必须记住三点：

1. **微信小程序构建产物不需要上传到腾讯云服务器**，它通过微信开发者工具上传到微信平台。
2. 腾讯云服务器需要的是 FastAPI 源码、Alembic migration、管理后台构建产物、数据库 SQL，以及服务器配置。
3. 正式小程序不能请求 `localhost`、`127.0.0.1` 或普通公网 IP，必须使用微信后台已配置的 **HTTPS 合法域名**。

## 2. 本项目的最小部署路线

建议严格按下面顺序执行，每完成一步再进入下一步：

```text
① 准备域名和服务器
→ ② 本地测试并构建
→ ③ Git Bash 打包服务器文件和数据库
→ ④ 上传到腾讯云 Windows Server
→ ⑤ 安装 Python、MySQL、Nginx
→ ⑥ 导入数据库并配置 FastAPI
→ ⑦ 先在服务器本机启动 FastAPI
→ ⑧ 配置 Nginx、域名和 HTTPS
→ ⑨ 构建并上传微信小程序
→ ⑩ 完成小程序、后台、API、MySQL 四层验收
```

这是“最小但完整”的路线。第一次不要同时引入 Docker、Kubernetes、负载均衡、Redis、对象存储等额外技术。

## 3. 开始前必须准备的资料

### 3.1 腾讯云侧

准备并记录：

- Windows 服务器公网 IP；
- Windows 管理员账号，通常为 `Administrator`；
- 服务器登录密码；
- 腾讯云实例地域；
- 一个已注册的域名；
- 两个子域名，例如：
  - `api.example.com`：FastAPI 接口；
  - `admin.example.com`：Element Plus 管理后台；
- 与域名匹配的 SSL 证书；
- 如果服务器位于中国大陆，域名需按腾讯云和微信平台要求完成备案/登记。

将本文中的：

```text
api.example.com
admin.example.com
```

全部替换为你自己的真实域名。

### 3.2 微信侧

准备：

- 微信小程序 AppID；
- 微信公众平台管理员权限；
- 微信开发者工具；
- 微信公众平台中可配置“服务器域名”的权限。

当前项目的 [`manifest.json`](../apps/miniprogram/src/manifest.json) 中：

```json
"mp-weixin": {
  "appid": "",
  "setting": { "urlCheck": false }
}
```

说明当前尚未填写真实微信小程序 AppID。正式构建前必须填写真实 AppID，并建议把 `urlCheck` 改为 `true`，让开发环境也按正式域名规则检查。

### 3.3 本地电脑侧

确认已有：

- Git Bash；
- Node.js；
- `pnpm.cmd`；
- `npm.cmd`；
- MySQL 8 客户端和 `mysqldump.exe`；
- 当前项目可以正常运行；
- FastAPI、H5、管理后台本地联调已经通过。

### 3.4 没有域名时能做到哪一步

如果现在只有腾讯云公网 IP、还没有域名或 HTTPS 证书：

- 可以完成服务器文件上传、MySQL 导入和 FastAPI 本机启动；
- 可以临时通过只允许自己 IP 的测试端口验证 API；
- **不能完成可发布的小程序部署**；
- 微信开发者工具的“不校验合法域名”只能临时调试，不能代替正式域名配置；
- 体验版和正式版最终仍需要已配置的 HTTPS 合法域名。

因此，如果还没有域名，建议先做到本文第 13 节，确认 FastAPI 和 MySQL 正常，同时开始域名、备案/登记和证书流程。

## 4. 腾讯云服务器究竟需要哪些文件

### 4.1 必须上传

服务器压缩包最终只需要下面内容：

```text
pet-life-server/
├─ backend/
│  ├─ app/                 # FastAPI 业务代码
│  ├─ migrations/          # Alembic migration
│  ├─ alembic.ini
│  └─ pyproject.toml       # Python 依赖
├─ admin-web/
│  ├─ index.html
│  └─ assets/              # Element Plus 构建产物
└─ database/
   └─ pet_life_prod.sql    # 本机数据库导出文件
```

### 4.2 不要上传

以下文件不应放进服务器发布包：

```text
.git/
.runtime/
node_modules/
.venv/
backend/.env.local
backend/data/*.db
apps/miniprogram/dist/
apps/miniprogram/src/
apps/admin-web/src/
tests/
本地日志
本地备份目录中的其他历史文件
```

原因：

- `.env.local` 包含数据库连接和 JWT 密钥，不能通过普通发布包传播；
- `.venv` 不能可靠地从本地 Windows 复制到另一台 Windows；
- `node_modules` 体积大，管理后台已经构建为静态文件；
- 小程序产物上传到微信平台，不放在服务器；
- 服务器只需运行 FastAPI，不需要运行 Vite 的 5173 或 5174 开发服务。

## 7. 配置腾讯云防火墙

在腾讯云实例详情页打开“防火墙”或“安全组”。最小规则如下：

| 端口 | 来源 | 是否开放 | 用途 |
|---|---|---:|---|
| TCP 80 | `0.0.0.0/0` | 是 | HTTP 跳转 HTTPS、证书验证 |
| TCP 443 | `0.0.0.0/0` | 是 | 小程序 API 和管理后台 HTTPS |
| TCP 3389 | 你当前公网 IP | 是 | Windows 远程桌面 |
| TCP 3306 | 不开放公网 | 否 | MySQL 只允许本机访问 |
| TCP 8000 | 不开放公网 | 否 | Uvicorn 只给 Nginx 访问 |
| TCP 5173/5174 | 不开放公网 | 否 | 这是本地 Vite 开发端口 |

还需要检查 Windows Defender 防火墙，允许 Nginx 或放行 TCP 80、443。

原则：公网只暴露 80 和 443；数据库、Uvicorn 和 Vite 端口都不直接暴露。

## 9. 创建服务器 MySQL 数据库

打开腾讯云 PowerShell：

```powershell
mysql -u root -p
```

进入 MySQL 后执行。下面密码只是占位符，必须换成新的强密码：

```sql
CREATE DATABASE pet_life_prod
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER 'pet_life_app'@'127.0.0.1'
  IDENTIFIED BY 'REPLACE_WITH_A_STRONG_DATABASE_PASSWORD';

GRANT ALL PRIVILEGES ON pet_life_prod.*
  TO 'pet_life_app'@'127.0.0.1';

FLUSH PRIVILEGES;
EXIT;
```

不要让 FastAPI 使用 MySQL `root` 账号。

### 9.1 导入本地业务数据

PowerShell 本身不支持传统的 `<` 重定向语法，因此使用 `cmd /c`：

```powershell
cmd /c "mysql -h 127.0.0.1 -P 3306 -u root -p pet_life_prod < C:\PetLifeMall\database\pet_life_prod.sql"
```

输入服务器 MySQL root 密码。

检查：

```powershell
mysql -h 127.0.0.1 -P 3306 -u root -p -e `
  "USE pet_life_prod; SHOW TABLES; SELECT * FROM alembic_version;"
```

完成导入并确认数据正常后，删除服务器上的明文 SQL 导出文件：

```powershell
Remove-Item -LiteralPath C:\PetLifeMall\database\pet_life_prod.sql
```

该删除不可恢复；必须在确认导入成功、且本地仍保留安全备份后执行。

## 11. 创建服务器 `.env.local`

不要把本机的 `backend/.env.local` 直接复制到服务器。服务器需要独立配置。

### 11.1 生成 JWT 密钥

```powershell
cd C:\PetLifeMall\backend
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

复制输出结果，不要发给其他人。

### 11.2 新建配置文件

```powershell
notepad C:\PetLifeMall\backend\.env.local
```

填写：

```dotenv
APP_ENV=production
APP_NAME=萌宠生活商城 API
DATABASE_URL=mysql+pymysql://pet_life_app:REPLACE_WITH_URL_ENCODED_PASSWORD@127.0.0.1:3306/pet_life_prod?charset=utf8mb4
FRONTEND_ORIGINS=https://admin.example.com
JWT_SECRET=REPLACE_WITH_THE_GENERATED_JWT_SECRET
JWT_ALGORITHM=HS256
JWT_EXPIRE_MINUTES=720
```

注意：

- 替换数据库密码、JWT 密钥和真实后台域名；
- 数据库密码若含 `@`、`:`、`/`、`#`、`%` 等字符，必须 URL 编码；
- 文件名必须是 `.env.local`，不要被记事本保存成 `.env.local.txt`；
- 生产配置不要使用项目示例密钥。


在服务器 `C:\PetLifeMall\backend` 执行：

```powershell
.\.venv\Scripts\python.exe -c "from getpass import getpass; from sqlalchemy import select; from app.db.session import SessionLocal; from app.models.entities import User; from app.core.security import hash_password; db=SessionLocal(); user=db.scalar(select(User).where(User.username=='admin')); password=getpass('New admin password: '); user.password_hash=hash_password(password); db.commit(); db.close(); print('admin password updated')"
```

密码输入不会显示。建议使用 16 位以上、包含大小写字母、数字和符号的独立密码。

如果要保留普通用户 `user` 用于体验测试，也必须用相同方法修改其默认密码，将命令中的 `admin` 换为 `user`。

## 17. 配置 Nginx

备份原配置：

```powershell
Copy-Item C:\nginx\conf\nginx.conf C:\nginx\conf\nginx.conf.backup
notepad C:\nginx\conf\nginx.conf
```

使用下面的最小配置，并替换域名和证书文件名：

```nginx
worker_processes  1;

events {
    worker_connections  1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile      on;
    keepalive_timeout 65;

    server {
        listen 80;
        server_name api.example.com admin.example.com;
        return 301 https://$host$request_uri;
    }

    server {
        listen 443 ssl;
        server_name api.example.com;

        ssl_certificate     C:/nginx/certificates/api.example.com_bundle.crt;
        ssl_certificate_key C:/nginx/certificates/api.example.com.key;
        ssl_protocols TLSv1.2 TLSv1.3;

        location / {
            proxy_pass http://127.0.0.1:8000;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }

    server {
        listen 443 ssl;
        server_name admin.example.com;

        ssl_certificate     C:/nginx/certificates/admin.example.com_bundle.crt;
        ssl_certificate_key C:/nginx/certificates/admin.example.com.key;
        ssl_protocols TLSv1.2 TLSv1.3;

        root C:/PetLifeMall/admin-web;
        index index.html;

        location / {
            try_files $uri $uri/ /index.html;
        }
    }
}
```

检查配置：

```powershell
cd C:\nginx
.\nginx.exe -t
```

只有看到配置成功提示后才启动：

```powershell
Start-Process C:\nginx\nginx.exe
```

修改配置后重新加载：

```powershell
cd C:\nginx
.\nginx.exe -t
.\nginx.exe -s reload
```

公网测试：

```powershell
Invoke-RestMethod https://api.example.com/health
Invoke-WebRequest https://admin.example.com/ -UseBasicParsing
```

浏览器访问：

```text
https://api.example.com/health
https://admin.example.com/
```


更新前，在服务器创建按时间命名的备份目录，例如：

```powershell
New-Item -ItemType Directory -Path C:\PetLifeMallBackup\20260821-01 -Force | Out-Null
```

## 23. 常见问题排查

### 23.1 小程序仍然请求 `127.0.0.1:8000`

原因：构建时没有传 `VITE_API_BASE_URL`，或者导入了旧产物。

重新构建：

```bash
cd /e/bishe27/wxMiniProgram/apps/miniprogram
VITE_API_BASE_URL="https://api.example.com/api/v1" pnpm.cmd build:mp-weixin
```

删除微信开发者工具中的旧项目，再导入新的 `dist/build/mp-weixin`。

### 23.2 浏览器能访问 API，小程序提示“不在以下 request 合法域名列表”

检查：

- 微信公众平台是否添加 `https://api.example.com`；
- 是否填成了公网 IP；
- 是否错误填写了 `/api/v1` 路径；
- 是否刚修改域名但开发者工具还未刷新；
- 是否导入了错误 AppID；
- 是否仍勾选或依赖“不校验合法域名”。

### 23.3 `502 Bad Gateway`

Nginx 已运行，但 FastAPI 没有运行。服务器本机执行：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Get-Process python -ErrorAction SilentlyContinue
```

再检查 `.env.local`、数据库密码和 Uvicorn 输出。

### 23.4 FastAPI 报数据库连接失败

检查：

```powershell
Get-Service *mysql*
mysql -h 127.0.0.1 -P 3306 -u pet_life_app -p pet_life_prod
```

如果 MySQL 密码有特殊字符，检查 `DATABASE_URL` 是否 URL 编码。

### 23.5 Nginx 无法启动

```powershell
cd C:\nginx
.\nginx.exe -t
Get-NetTCPConnection -LocalPort 80,443 -ErrorAction SilentlyContinue
```

常见原因：

- 证书路径错误；
- `nginx.conf` 使用了错误的反斜杠；
- 80 或 443 已被 IIS/其他程序占用；
- 配置缺少分号；
- 证书与私钥不匹配。

### 23.6 管理后台页面正常但接口报 CORS

检查服务器：

```dotenv
FRONTEND_ORIGINS=https://admin.example.com
```

修改后必须重启 FastAPI。

### 23.7 服务器内存不足

2 核 2GB 实例的最小设置：

- Uvicorn `--workers 1`；
- 不在服务器运行 Vite；
- 不安装 Docker Desktop；
- Nginx `worker_processes 1`；
- MySQL、Python 和 Nginx 之外不运行大型服务；
- 观察任务管理器内存；
- 数据增长后优先升级到 2 核 4GB 或使用腾讯云数据库。

## 25. 本项目部署结论

对于当前项目，腾讯云服务器最少需要：

```text
Windows Server
+ Python 3.12
+ MySQL 8.0
+ Nginx
+ backend/app
+ backend/migrations
+ backend/alembic.ini
+ backend/pyproject.toml
+ apps/admin-web/dist 的静态文件
+ 服务器独立 .env.local
+ SSL 证书和域名
```

腾讯云服务器不需要：

```text
微信小程序源码/构建产物
Node.js 和 Vite 开发服务器
本机 .venv
本机 node_modules
本机 .env.local
公网开放 MySQL 和 Uvicorn 端口
```

第一次部署的成功标准不是“文件已上传”，而是同时满足：

```text
HTTPS API 正常

```
