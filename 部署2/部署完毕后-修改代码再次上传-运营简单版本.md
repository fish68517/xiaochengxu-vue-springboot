# 3. 电梯维修以后迁到自己的腾讯云服务器

这里我建议一个原则：

> **电梯自己的服务器继续保持现在完全相同的目录和端口结构。**

例如新服务器：

```text
C:\ElevatorRepair

后台      8082
H5        8083
FastAPI   8100
MySQL     3306
```

这样以后维护命令**完全不用重新学习**。

假设新服务器 IP：

```text
<电梯服务器IP>
```

后台仍然构建：

```powershell
cd "E:\bishe27\小程序\电梯维修\admin-web"

$env:VITE_API_BASE_URL="/api"

npm.cmd run build
```

H5：

```powershell
cd "E:\bishe27\小程序\电梯维修\miniprogram"

$env:VITE_API_BASE_URL="/api"

npm.cmd run build:h5
```

两个压缩包还是：

```text
elevator-admin-update.tar.gz
elevator-h5-update.tar.gz
```

上传到**电梯自己的腾讯云服务器**：

```text
C:\packages\ElevatorRepair\
```

服务器仍然执行：

```powershell
Remove-Item C:\ElevatorRepair\admin-web\* -Recurse -Force

tar -xzf `
C:\packages\ElevatorRepair\elevator-admin-update.tar.gz `
-C C:\ElevatorRepair\admin-web
```

H5：

```powershell
Remove-Item C:\ElevatorRepair\miniprogram-h5\* -Recurse -Force

tar -xzf `
C:\packages\ElevatorRepair\elevator-h5-update.tar.gz `
-C C:\ElevatorRepair\miniprogram-h5
```

微信小程序灰度只需要把 IP 换掉：

```powershell

npm.cmd run build:mp-weixin
```

以后有正式域名和 HTTPS，就变成：

```powershell

npm.cmd run build:mp-weixin
```

# 如果 FastAPI 后端代码也修改了

这个需要和前端区别开。

以电梯为例，本机打包：

```powershell
cd "E:\bishe27\小程序\电梯维修"

tar -czf release\elevator-backend-update.tar.gz `
    --exclude=.venv `
    --exclude=.env `
    --exclude=.env.development `
    --exclude=.env.production `
    --exclude=__pycache__ `
    backend\app backend\alembic backend\alembic.ini backend\requirements.txt
```

上传以后**不要覆盖服务器 `.env` 和 `.venv`**。

然后：

```text
更新 backend 源码
→ pip install -r requirements.txt（依赖有变化才执行）
→ alembic upgrade head（数据库结构有变化才执行）
→ 重启对应 FastAPI
→ /api/health 验证
```

萌宠也是同样原则，只是服务器目录和端口分别是：

```text
萌宠：
C:\PetLifeMall
FastAPI 8000

电梯：
C:\ElevatorRepair
FastAPI 8100
```

## 最后记住这个维护口诀

| 修改内容      | 要做什么                                         |
| --------- | -------------------------------------------- |
| 管理后台改了    | `build → tar.gz → 上传 → 覆盖 admin-web`         |
| H5改了      | `build:h5 → tar.gz → 上传 → 覆盖 miniprogram-h5` |
| 微信小程序改了   | `build:mp-weixin → 微信开发者工具`                  |
| FastAPI改了 | 上传 backend → 重启对应 FastAPI                    |
| 数据库模型改了   | 额外 `alembic upgrade head`                    |
| 只是前端改了    | **不用重启 FastAPI/Nginx**                       |
| Nginx配置改了 | `nginx.exe -t → nginx.exe -s reload`         |

你以后日常更新大部分情况下，其实就是：

```text
本地 build
→ tar.gz
→ 上传
→ 删除服务器旧静态文件
→ 解压新文件
→ 浏览器 Ctrl+F5
```

这就是最简单、最适合目前两个项目的维护方式。
