### 三个常见疑问：为什么公钥、私钥、APIv3 密钥都需要？

#### 1. 有商户私钥和证书，为什么没有单独的商户公钥？

**不是没有，而是商户公钥已经包含在 `apiclient_cert.pem` 证书中。**证书还包含商户号、公司名称、序列号、有效期等信息；`apiclient_key.pem` 则单独保存商户私钥。证书 PEM 本身不包含私钥，不能与私钥文件混为一谈。

商户服务器使用私钥对支付请求签名，微信支付使用对应的商户公钥验证签名。因此本次“商户证书＋商户私钥”已经配套，无需客户再寻找一个独立的商户公钥文件；如技术上需要，可从证书提取，但提取出来的仍是商户公钥。见[官方商户 API 证书说明](https://pay.wechatpay.cn/doc/v3/merchant/4012072428)。

#### 2. 有微信支付公钥和公钥 ID，为什么没有微信支付私钥？

**微信支付私钥由微信支付平台自己保管，不会提供给商户，也不需要客户申请或下载。**微信支付用它对返回的应答和支付通知签名，我们只需使用 `pub_key.pem` 验证签名。公钥 ID 用于识别应使用哪一把微信支付公钥，不是私钥，也不能代替公钥文件。

这和商户自己保管商户私钥是同一个道理：谁发送消息，谁用自己的私钥签名；接收方用发送方的公钥核验。公钥不能用于推导私钥。不要向客户索取“微信支付平台私钥”，也不要把 APIv3 密钥当成这把私钥。签名与验签的职责见[官方 APIv3 签名验签总述](https://pay.wechatpay.cn/doc/v3/merchant/4012365342)。

#### 3. 已有上述公私钥，为什么还需要 APIv3 密钥？

**因为“验证消息来源”和“解开消息内容”是两项不同的工作。**微信支付公钥负责验证通知签名；支付成功通知中的业务数据还经过加密，商户服务器需要 APIv3 密钥解密，才能取得订单号、金额、交易状态等内容。

APIv3 密钥是商户在商户平台设置、由双方用于相关加解密的 **32 字节对称密钥**，不是 PEM 文件，不是 RSA 私钥，也不是服务号 AppSecret。支付通知的 `resource.ciphertext` 需要结合 APIv3 密钥、`nonce` 和 `associated_data` 解密；具体规则见[官方支付成功回调通知](https://pay.wechatpay.cn/doc/v3/merchant/4012791861)。

正确的处理顺序是：先验证微信通知签名，再解密业务内容，随后核对订单、商户、金额和交易状态，最后幂等更新订单。**只有验签成功，不代表已经读到了支付结果；只有解密成功，也不能省略通知验签。**即使能够弹出支付窗口或用户已付款，APIv3 密钥错误仍可能导致系统无法处理支付通知，不能据此直接将订单标记为已支付。

| 要完成的事 | 谁持有／使用什么 | 本项目资料 |
|---|---|---|
| 向微信证明请求来自商户 | 商户保管私钥并签名；微信用商户公钥验签 | `apiclient_key.pem`；商户公钥在 `apiclient_cert.pem` 内 |
| 确认返回的通知来自微信支付 | 微信保管自己的私钥并签名；商户用微信支付公钥验签 | `pub_key.pem` ＋ `PUB_KEY_ID_...` |
| 读取通知中的加密业务数据 | 微信支付加密，商户使用同一 APIv3 密钥解密 | TXT 中标注的 APIv3 密钥，仅配置在服务端 |

**结论：当前没有“缺商户公钥”或“缺微信支付私钥”的问题；现有核心凭据种类齐全，接下来核对配套关系、完成云端配置和真实支付通知验签／解密联调即可。**

本次仅核对附件并更新清单，**未将附件密钥写入仓库、前端或本 Markdown，也未写入云端环境变量**。证书与私钥匹配不等于已具备支付权限或已支付成功。原始 TXT 含敏感凭据，不要作为普通客户说明文档转发；若曾公开分享或进入不受控渠道，应在商户平台更换相应凭据并同步云端配置。

## 技术部署补充

本次需要发布阿里云 `code/apps/client/uniCloud-aliyun/cloudfunctions/game-service` 和管理后台 `code/apps/admin/dist/build/h5`（站点 `/admin/`）。无需因本次字段修复重新发布客户小程序。云端配置不由本地代码自动写入。

支付模式为 wechat 时，正式环境新建支付流水前会检查品牌映射和凭据完整性；后台已填写的商户号必须与映射商户号一致。历史使用 `env:wechat-pay` 占位引用的流水，只对 PENDING 且没有微信预支付标识的记录，在新配置校验通过后更新引用；其他已有支付流水保持原引用。

`WECHAT_PAY_CONFIG_MAP` 配置结构示例（示例品牌 Code 和主体 ID 必须核对替换；不包含真实密钥）：

```json
{
  "production": {
    "实际品牌code": {
      "entityId": "实际收款主体标识",
      "secretRef": "secret://xinghe/wechat-pay/production",
      "envPrefix": "PAY_XINGHE",
      "appId": "wxc2da39cc9c2d35da",
      "mchid": "1116677386",
      "boundAppIds": ["wxc2da39cc9c2d35da"],
      "h5Enabled": false
    }
  }
}
```

此处 `h5Enabled=false` 仅表示未启用微信外浏览器的 H5 支付，不影响小程序 WebView 中的 JSAPI 支付。开通微信外 H5 支付后再调整。配置中的 boundAppIds 仍须与微信平台实际绑定结果一致。
