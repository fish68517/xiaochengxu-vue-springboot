# 服务号网页授权环境变量与部署核查（2026-09-12）

## 本次定位

小程序日志中的 `WebView LOAD SUCCESS` 仅表示 `https://h5.qmhyjoy.com` 页面被加载，不能证明 H5 下单页已完成商品读取、服务号网页授权或云函数调用。

已从当前代码和线上首页确认三个独立问题：

1. 客户端生产配置曾写成 `OAUTH_APPID`，而 `apps/client/src/api.js` 只读取 `VITE_OAUTH_APPID`。Vite 不会把无 `VITE_` 前缀的变量注入浏览器构建，导致 H5 页面判断“未配置服务号网页授权”。现已改成 `VITE_OAUTH_APPID`。
2. 阿里云 `game-service/lib/oauth.cjs` 曾读取 `WECHAT_OFFICIAL_APPID/WECHAT_OFFICIAL_SECRET`，而当前云函数按用户配置的是 `OAUTH_APPID/OAUTH_SECRET`。即使 H5 成功发起授权，回调换取 openid 时仍会因读不到变量而失败。现已将阿里云云函数副本统一读取 `OAUTH_APPID/OAUTH_SECRET`；`code/uniCloud-tcb` 不参与本次部署，也不再修改。
3. 最新复核：线上首页已更新为 `/assets/index-W98LgEyp.js`，下单页资源为 `pages-h5-order-index.DyRa1alR.js`；该线上资源已包含“请稍候，不要关闭页面。。。”、服务号 AppID 和超时处理。此前“服务器仍是旧版”的判断已不适用于本次核查。截图仍无省略号，说明当前微信显示内容与本次服务器响应不一致，需排查 WebView 缓存或未重新打开的旧页面。资源名仅用于此次核查。

网页授权失败后，H5 下单页现会显示错误状态，不再吞掉异常后自动重复授权。兑换成功时还会清除普通查询参数和 Hash 路由中的一次性 `code/state`，避免刷新后再次兑换已使用的 code。尚未在真实手机上完成授权回调与下单闭环验证。

## 关于“正在准备订单”一直旋转

最新截图明确未显示用户添加的“。。。”。现已在 WebView 入口的 `#` 前增加 `?webview_rev=打开时间`，每次打开使用不同的 HTML 请求地址；仅在 `#` 后加参数不会改变服务器收到的 HTML 请求。OAuth 回调地址也携带新的入口参数。

新增 H5 控制台日志前缀 `[H5Order]`，版本标识为 `20260912-order-diagnostics-1`。日志记录阶段和耗时，不记录 token、授权 code、openid 或完整接口响应。在 WebView 对应的 H5 控制台筛选此前缀：

| 最后一条阶段日志 | 可定位的范围 |
|---|---|
| 完全没有该版本日志 | 新诊断版 H5 未执行，先核对静态发布和实际 WebView 地址 |
| `setup`，没有 `onLoad` | 页面脚本已初始化，但页面加载回调未进入 |
| `getH5Product:start` | 已发出商品读取，随后应有 success 或 20 秒 timeout 错误 |
| `getH5Product:success` 后 `prepare:error` | 请求已返回，需检查商品响应或表单处理 |
| `oauthRedirect:start` | 商品读取已通过，正在发起服务号授权 |
| `oauthExchange:error` | 已回调到 H5，但换取服务号身份失败 |
| `form:ready` | 商品和准备流程已完成，应显示下单表单 |

外层 `[WebView DEBUG] LOAD SUCCESS` 不能代替上述 H5 内部日志。当前没有取得用户设备中的这些运行日志，不能据截图断言某个云函数请求已失败。

该提示在 H5 下单页的旧模板里原本就存在，看到文字不能证明新 H5 已部署。截图中的小程序侧 `WebView LOAD SUCCESS` 只覆盖 WebView 页面加载；H5 内部还会异步执行 `getH5Product`，此请求不返回或服务号授权跳转未完成时，旧页面可能一直显示加载状态。单凭截图不能判定究竟卡在哪一个请求。

现已将 `pages/h5-order/index` 限定为 H5 页面；小程序只保留 `pages/order/webview-shell` 作为下单入口。构建后的 `mp-weixin/app.json` 已不含 H5 下单页。H5 商品加载、网页授权兑换和微信授权跳转增加 20 秒可见超时，避免请求或跳转悬而未决时无限旋转；超时后会显示对应错误。此修改也必须重新发布 H5 才能生效。

## 环境变量统一口径

| 位置 | 变量 | 值的性质 |
|---|---|---|
| 客户 H5 构建环境（`apps/client/.env.production`） | `VITE_OAUTH_APPID` | 服务号 AppID；公开配置，不是小程序 AppID |
| `game-service` 云函数环境 | `OAUTH_APPID` | 同一个服务号 AppID |
| `game-service` 云函数环境 | `OAUTH_SECRET` | 服务号 AppSecret；仅服务端保存，不能进入 Git、前端环境变量或 H5 产物 |

`WECHAT_MP_APPID/WECHAT_MP_SECRET` 是小程序 `code2session` 登录用的另一组变量，不能替代服务号网页授权变量。

## 使修复生效

1. 在 HBuilderX 中确认部署的是当前项目 `apps/client/uniCloud-aliyun/cloudfunctions/game-service`，重新上传并部署 `game-service` 云函数。仅修改云函数环境变量不会更新已发布的旧代码。
2. 在 `code/apps/client` 执行 `npm run build:prod`，本项目当前命令输出目录为 `apps/client/dist/build/h5`。将该目录的完整内容重新发布到 `https://h5.qmhyjoy.com/` 对应的站点根目录；不要上传旧的 `dist/build/web`。
3. 用无缓存请求检查线上首页引用的入口 JS 已换为新构建资源，并在微信小程序 WebView 中重新打开下单链接。若入口仍是旧哈希，先处理静态托管发布或缓存，不要继续调整 OAuth 代码。
4. 若新构建生效后仍失败，分别检查 H5 的 `getH5Product`、跳转至微信 `oauth2/authorize`、回调后的 `oauthExchange` 请求及返回码，并核对微信公众平台中服务号网页授权域名是否为 `h5.qmhyjoy.com`。只看小程序侧的 WebView `load` 日志不足以定位这一步。

上传的截图包含服务号 AppSecret。应在服务号后台轮换该密钥，再同步更新云函数 `OAUTH_SECRET`；本文档不记录密钥值。
