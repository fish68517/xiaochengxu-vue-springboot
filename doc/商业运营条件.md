## 3. 商业运营主体与资质条件

### 3.1 经营主体

建议使用公司或具备相应经营范围的个体工商户作为统一运营主体，并保证以下名称尽量一致：

- 营业执照主体；
- 域名 ICP 主体；
- 小程序主体；
- 服务号主体；
- 微信支付商户主体；
- 用户协议和隐私政策中的运营者；
- 发票和收款主体。

如果多个品牌属于不同公司，不能只换小程序名称和 AppID 就共用一个普通商户号。应选择下列一种模式：

1. 每个品牌独立主体、独立小程序、独立商户号、独立 uniCloud 生产空间；
2. 由具备微信支付服务商能力的主体接入特约商户，使用服务商/子商户/子 AppID 模式；
3. 所有品牌确实属于同一经营主体，由同一主体收款，但仍要在合同、账务和品牌授权上明确。

微信支付官方资料明确区分普通商户 `MCHID-AppID` 与服务商 `MCHID-SubMCHID-SubAPPID` 等绑定模式，因此多主体品牌必须先确定支付接入模型。[微信支付绑定关系说明](https://pay.wechatpay.cn/doc/v3/merchant/4012062239)

### 3.2 ICP 备案、经营许可和小程序备案

需要办理或评估：

- 客户 H5、后台和 API 自定义域名的 ICP 备案；
- 小程序的 APP/小程序备案；
- 公安联网备案是否适用；
- 如果实际模式属于经营性互联网信息服务，是否需要 ICP 许可证；
- 如果提供网络文化、直播、语音社交、虚拟道具或游戏运营等扩展业务，是否需要文化、视听或其他前置许可。

工信部规定，境内提供互联网信息服务的 APP 主办者应履行备案，范围包含小程序、快应用等分发形态；新业务应先备案后开展服务。[工信部 APP 备案通知](https://www.gov.cn/zhengce/zhengceku/202308/content_6897341.htm?type=mobile-internet)

非经营性互联网信息服务实行备案，经营性互联网信息服务实行许可。当前项目有订单、平台佣金和服务撮合属性，是否构成需要许可的经营性互联网信息服务，应结合实际收费模式向所在地通信管理局或备案接入商确认，不能只凭“做了 ICP 备案”自行判断。[互联网信息服务备案审批服务指南](https://hunca.miit.gov.cn/bsfw/bszn/art/2024/art_7ef0d8bd3b0d433ba4b9b277f883f74d.html)

### 3.3 游戏陪玩业务专项评估

上线前需要由律师和微信审核服务商确认实际商品类型与小程序类目是否允许，重点评估：

- 是否涉及代练、账号租售、外挂、账号共享或违反游戏厂商用户协议的服务；
- 是否提供语音房、直播、陌生人社交、用户公开发布内容；
- 是否使用平台虚拟币、充值余额或可提现积分；
- 是否面向未成年人提供陪玩、付费或社交服务；
- 服务描述和宣传是否存在“保证上分”“绝对成功”等不当承诺；
- 是否需要对接单人员实行实名、年龄和技能审核。

建议商业 V1 明确禁止：外挂、代充值、账号买卖、诱导私下交易、涉黄涉赌、未成年人接单，以及未经游戏厂商允许的高风险账号托管行为。

### 3.4 电子商务平台责任

如果平台撮合客户与独立接单人员，运营者很可能承担平台经营者义务，需要建立：

- 接单人员身份、联系方式和必要资质的核验与持续更新；
- 服务信息、交易信息和投诉处理记录；
- 平台服务协议和交易规则；
- 接单人员进入、退出、冻结和申诉制度；
- 消费者权益、退款、争议和赔偿机制；
- 违法违规服务巡查与下架机制；
- 交易和服务信息至少满足法定保留期。

《电子商务法》要求平台记录并保存商品/服务和交易信息，交易完成后保存不少于三年，并制定公开、公平、公正的平台服务协议和交易规则。[中华人民共和国电子商务法](https://www.npc.gov.cn/WZWSREL3pncmR3L25wYy9sZnp0L3JseXcvMjAxOC0wOC8zMS9jb250ZW50XzIwNjA4MjcuaHRt)

### 3.5 税务、发票、劳动和结算

必须在上线前书面确定：

- 平台向客户销售服务，还是接单人员向客户销售、平台仅收佣金；
- 平台应开具什么发票；
- 接单人员是员工、劳务人员、个体经营者还是平台内经营者；
- 平台是否承担个人所得税代扣代缴或涉税信息报送义务；
- 退款时收入、平台佣金和接单人员收入如何冲销；
- 财务日结、月结和微信支付账单如何对账。

当前代码使用“平台收全款—形成接单人员钱包—人工确认提现”的模型。真实商业运营前必须由支付机构和律师评估是否存在无证资金归集、二次清算或沉淀用户资金风险。优先考虑微信支付服务商分账/特约商户等合规产品，不应把数据库中的 `wallets` 余额当成可自由流通的用户储值账户。

## 4. uniCloud、域名和微信平台条件

### 4.1 是否需要 uniCloud 认证

需要区分两种“认证”：

1. DCloud 开发者账号实名认证：商业使用 uniCloud、创建和管理正式空间、添加协作者时应完成；协作者也需要实名认证；
2. `uni实人认证`：这是对平台用户/接单人员做人脸实名核验的付费产品，不是使用普通云函数的必选项。

本项目商业上线至少需要完成 DCloud 账号实名认证、生产空间购买/开通、项目与服务空间关联和成员最小权限配置。DCloud 官方说明，一个服务空间包含独立的云函数、数据库和存储资源，项目关联空间后才能上传资源，协作者需实名认证。[uniCloud 服务空间说明](https://doc.dcloud.net.cn/uniCloud/concepts/space)

如果决定对接单人员做人脸实名，才需要额外开通 `uni实人认证` 或其他合规实名认证服务。DCloud 的实人认证服务要求开发者账号先完成实名认证，并属于按量或资源包计费服务。[uni实人认证开通说明](https://doc.dcloud.net.cn/uniCloud/frv/service.html)

### 4.2 uniCloud 生产空间

建议建立：

| 空间 | 用途 | 数据 |
|---|---|---|
| development | 开发，可继续使用本地环境 | 演示数据 |
| staging | 真实微信和最小金额联调 | 专用测试数据，禁止复制生产身份证 |
| production | 正式运营 | 正式业务数据 |

每个空间应配置：

- 明确的空间 ID；
- 云函数、数据库、云存储和静态托管；
- 预算、套餐和余额告警；
- 函数日志、调用量、超时和错误率告警；
- 数据库容量和慢查询监控；
- 成员最小权限和操作审计；
- 生产 Secret；
- 独立备份和恢复演练。

uniCloud 套餐或按量余额耗尽可能导致服务停止，因此生产环境必须设置余额、资源阈值和续费告警。[uniCloud 计费说明](https://doc.dcloud.net.cn/uniCloud/price)

### 4.3 是否需要域名绑定

商业上线需要绑定正式自定义域名，不能长期使用测试域名。建议：

| 域名 | 用途 | 绑定位置 |
|---|---|---|
| `h5.example.com` | 客户 H5、web-view、H5 支付发起页 | 客户静态托管空间 |
| `admin.example.com` | 工作台和管理后台 | 后台静态托管空间 |
| `api.example.com` | 支付回调、客服回调 | 云函数 URL 化/网关 |

需要完成：

- 域名注册和实名；
- ICP 备案；
- DNS 解析；
- HTTPS 证书；
- uniCloud 静态托管自定义域名；
- uniCloud Web 安全域名/跨域白名单；
- 小程序 request、uploadFile、downloadFile 合法域名；
- 小程序 web-view 业务域名；
- 服务号网页授权域名和 JS 接口安全域名；
- 微信支付 H5 支付域名和 JSAPI 支付授权目录。

uniCloud 官方说明，自定义域名访问云函数时，需要在服务空间跨域配置中添加该域名；默认测试域名受限，不适合作为正式商业域名。[uniCloud 前端网页托管与跨域](https://doc.dcloud.net.cn/uniCloud/hosting?id=routing)

对于小程序直连 uniCloud，云函数自有域名可用于小程序联网域名；但只要使用前端网页托管，正式自定义域名仍涉及备案、绑定和跨域配置。[uniCloud 发行说明](https://doc.dcloud.net.cn/uniCloud/publish.html)

### 4.4 微信小程序与服务号

每个正式品牌至少需要：

- 已认证的小程序主体和 AppID；
- 完成小程序备案；
- 正确的小程序服务类目；
- 隐私保护指引；
- 用户协议与隐私政策；
- 客服能力；
- 订阅消息模板；
- web-view 业务域名；
- API 和文件域名；
- 体验版、审核版和正式版发布权限。

客户 H5 在微信内进行 JSAPI 支付时，还需要已认证服务号、服务号 AppID/Secret、网页授权域名、JS 接口安全域名和支付授权目录。

### 4.5 微信支付商户

需要：

- 微信支付商户号；
- 商户号与实际 AppID 的绑定；
- JSAPI 支付产品权限；
- H5 支付产品权限；
- 商户 API 私钥和证书序列号；
- APIv3 密钥；
- 支付通知 HTTPS 地址；
- 退款权限；
- 如自动向接单人员出款，需另外申请对应产品和权限。

微信支付官方资料要求 AppID 与商户号绑定；JSAPI 支付需要申请权限并配置实际公众号/小程序场景。[微信支付开发参数](https://pay.wechatpay.cn/doc/v3/merchant/4013070756)、[JSAPI 支付申请指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791854)

H5 支付域名必须在商户平台配置，域名应完成 ICP 备案，经营内容需与商户类目相符；域名、商户主体不一致时还可能需要授权材料。[微信支付 H5 支付域名配置](https://pay.wechatpay.cn/doc/v3/merchant/4013287193)

## 5. 当前代码必须完成的 P0 商用整改

以下问题不是“以后优化”，而是建议在真实收款前完成的上线阻断项。

### P0-01：真实 uniCloud 运行尚未验证

现状：

- 云函数 repository 是按 uniCloud API 编写；
- 自动化测试使用 mock uniCloud；
- 开发计划明确真实 staging 未完成；
- `uniCloud-tcb/cloudfunctions/README.md` 中“已部署 pwfinal、7 个 schema”的说明已过时，与当前 26 个 schema 不一致，不能作为现网证据。

需要完成：

- 在全新 staging 空间执行云函数、schema、索引上传；
- 对 104 个 action 中的核心写操作做真实数据库回归；
- 验证事务、条件更新和索引冲突行为；
- 更新云端交接说明，删除过时部署结论。

### P0-02：H5 到 uniCloud 的生产调用链未验证

现状：本地 UI 冒烟通过 `VITE_API_BASE=http://127.0.0.1:4176` 访问镜像 API；生产 H5 计划在 `VITE_API_BASE` 为空时调用 `uniCloud.callFunction`。

需要完成：

- 在真实静态托管页面确认 `uniCloud.callFunction` 存在；
- 配置 H5 自定义域名到云空间 Web 安全域名；
- 用浏览器 Network/Console 验证客户、工作台、管理端均可调用；
- 如果目标托管环境不提供 H5 云函数 SDK，必须增加正式 HTTP API 网关，不得把 `/pay-notify` 回调入口当成通用 API。

### P0-03：客服下单链接路径与实际 H5 路由不一致

现状：客户 H5 使用 hash 路由，实际页面是：

```text
/#/pages/h5-order/index?token=...
```

但 `game-service` 和 `wechat-callback` 当前生成：

```text
/h5-order?token=...
```

在纯静态托管上很可能 404 或无法进入正确页面。

需要统一为实际 hash 路由，并增加真实客服消息点击测试。

### P0-04：多品牌微信支付 Secret 实际未按品牌解析

现状：支付单会记录 `brand.channelRefs.paymentSecretRef`，但实际 `getPayClient()` 仍从全局 `WECHAT_PAY_*` 读取一套商户配置，没有根据 `secretRef` 加载不同品牌的商户号和私钥。

另外，`ensurePayment` 检查的是 `WECHAT_PAY_MCH_ID`，实际配置键是 `WECHAT_PAY_MCHID`，存在键名不一致。

需要根据商业模型选择：

- 同一主体同一商户：明确允许哪些品牌共享商户，并修正键名；
- 多个独立商户：实现 `secretRef → Secret 管理 → PayClient` 的品牌级解析与缓存；
- 服务商模式：改造支付参数为服务商/子商户/子 AppID 协议；
- 当前代码未改造前，最安全方案是一个独立经营主体/品牌使用一个独立生产空间。

### P0-05：提现目前是人工记账，不是真实出款

现状：

- `startWithdrawalPayment` 只把记录改为 `PAYING`；
- `markWithdrawalPaid` 由管理员输入批次号后记账；
- `transferNotify` 直接返回“二期预留”；
- 没有真实商家转账、银行出款或回调验签。

商业方案必须二选一：

1. 保留人工财务出款：双人复核、付款凭证、银行/微信账单导入、每日对账、限额和审计；
2. 接入合规自动出款：申请对应支付产品、实名校验、回调验签、幂等、失败重试、风控和对账。

不得向接单人员宣传“系统自动到账”，除非真实出款链已完成验收。

### P0-06：系统任务入口缺少生产级调用保护

现状：`transferNotify`、`timeoutCloseUnpaidOrders`、`timeoutMarkPool`、`timeoutRejectAssignments` 被放入无会话的 `SYSTEM_ACTIONS`。

虽然超时操作具有条件更新，但任何能调用云函数的客户端都有机会触发这些动作。需要：

- 从普通客户端 action 入口移除系统任务；
- 只允许 uniCloud 定时触发器或内部服务调用；
- 使用独立 `SCHEDULER_SECRET`、平台触发上下文或可信来源校验；
- 给任务增加分布式锁、执行批次和审计；
- 在云空间真正配置定时触发器。当前云函数目录没有可直接确认的触发器配置。

### P0-07：敏感个人信息没有按注释真正加密

现状：schema 描述手机号、微信号等“加密存储”，但服务代码实际直接保存 `phone`、`contactPhone`、`withdrawWechat`、`realName` 等明文。身份证附件仅写入：

```text
encrypted: true
watermarkText: "姓名 时间"
```

当前代码没有真正加密文件，也没有把水印渲染到身份证图片像素中。

需要完成：

- 字段级加密和密钥轮换；
- 检索字段使用不可逆 HMAC/盲索引，不直接按明文手机号查询；
- 身份证私有桶、服务端真实水印、短期签名 URL；
- 查看身份证的专门权限、二次确认和审计；
- 下载限制、文件生命周期和到期删除；
- 文件 MIME、扩展名、大小、恶意文件和图片解码校验；
- 明确是否真的需要保存身份证图片，能通过第三方实名结果完成的不要长期留图。

### P0-08：后台密码与限流不满足生产要求

现状：后台密码使用无盐 SHA-256；登录限流只存在于单个云函数实例内存中，多实例间不共享。

需要：

- 使用 Argon2id、scrypt 或 bcrypt 等带盐慢哈希；
- 旧密码登录后渐进迁移；
- 数据库/Redis 级统一限流；
- 管理员 MFA；
- 设备/IP 风险控制；
- 密码复杂度、泄漏密码拦截和安全重置；
- 管理后台限制访问来源或增加零信任/VPN 网关。

### P0-09：隐私、用户协议和账号权利页面缺失

在业务源码中未发现正式隐私政策、用户协议、接单人员协议、账号注销或个人信息权利页面。

上线前至少增加：

- 用户服务协议；
- 隐私政策；
- 第三方 SDK/共享清单；
- 个人信息收集清单；
- 敏感个人信息单独同意；
- 接单人员入驻与结算协议；
- 退款、售后和异议规则；
- 未成年人规则；
- 账号注销、信息查阅、更正、复制和删除入口；
- 客服、投诉举报和个人信息负责人联系方式。

《网络数据安全管理条例》要求个人信息处理规则集中公开、醒目易懂，并说明处理目的、方式、种类、保存期限及用户查阅、更正、删除、注销和撤回同意的途径；还要求建立数据安全事件预案和投诉渠道。[网络数据安全管理条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)

### P0-10：生产备份、告警和恢复还没有接上真实平台

现状：

- `backup-db.mjs` 只备份本地内存镜像；
- `restore-drill.mjs` 只恢复到内存；
- `alert.mjs` 的 webhook 只是预留标记，不会真的发送；
- 没有经验证的生产 RPO/RTO。

需要：

- 使用 uniCloud/底层云厂商的生产数据库导出或备份能力；
- 对 26 个集合做完整备份；
- 加密异地保存；
- 每月在隔离空间恢复演练；
- 接入真实告警渠道；
- 定义 RPO、RTO 和负责人；
- 支付、退款、提现异常必须实时告警；
- 余额不足、套餐超限、证书到期必须提前告警。

### P0-11：正式业务规则尚需书面确认

当前开发计划仍说明正式佣金、退款和仲裁规则需要业务确认。必须形成经法务/财务/运营签字的版本化规则：

- 什么时候算开始服务；
- 什么证据证明完成；
- 各状态取消和退款比例；
- 平台佣金和接单人员收入确认时点；
- 退款后如何追佣；
- 钱包负数如何处理；
- 提现周期、手续费、最低金额和风控；
- 异议受理期限和裁决权限；
- 规则变更是否只作用于新订单。

代码已经保存订单、品牌和佣金规则快照，应继续坚持“旧订单使用下单时规则，不被新规则追溯修改”。

## 7. 结合当前项目的推荐部署方案

### 7.1 推荐方案选择

如果近期只有一个实际经营主体，建议采用：

```text
同一经营主体
  ├─ 一个 production uniCloud 空间
  ├─ 一个微信支付商户号

  ├─ 一个或多个同主体小程序 AppID
```

```text
品牌 A：独立 uniCloud production 空间 + 独立数据库 + 独立商户号
```

该方案成本高一些，但可避免当前全局 `WECHAT_PAY_*`、`WECHAT_MP_*` Secret 造成品牌间商户配置串用。待完成真正的 Secret 路由和服务商支付模式后，再评估合并空间。

### 7.6 H5 与域名部署

建议将客户和后台托管分开：

- 客户域面向公网；
- 后台域增加 MFA、IP 白名单、VPN 或零信任访问；
- API 回调域仅暴露所需 URL 化路径；
- 管理后台不与支付回调共用前端静态域；
- 所有域名强制 HTTPS、HSTS、合理 CSP 和安全响应头；
- 配置 CDN 缓存时，`index.html` 应短缓存，带 hash 的静态资源可长缓存；
- 云存储身份证和争议证据不得公开读。

### 7.7 定时任务

修复 P0-06 后，在 uniCloud 配置：

| 任务 | 建议频率 | 作用 |
|---|---:|---|
| `timeoutCloseUnpaidOrders` | 每 1～5 分钟 | 关闭支付超时订单 |
| `timeoutMarkPool` | 每 5 分钟 | 标记无人抢单超时 |
| `timeoutRejectAssignments` | 每 1～5 分钟 | 处理指派超时 |
| 支付主动查单补偿 | 每 5～10 分钟 | 回调丢失时查询支付状态，当前需新增 |
| 退款状态补偿 | 每 5～10 分钟 | 退款回调丢失时查询，当前需新增 |
| 日终对账 | 每天 | 微信账单、订单、支付、退款和钱包核对，当前需新增 |
| 备份检查 | 每天 | 确认生产备份成功，当前需新增 |

任务必须记录批次 ID、开始/结束、扫描数、成功数、失败数和重试结果。

```powershell
$env:HX_CLI = '<HBuilderX cli.exe绝对路径>'
```

## 10. 商业上线 Go/No-Go 清单

### 主体与平台

- [ ] 经营主体、经营范围和品牌授权确认；
- [ ] ICP 备案/许可结论确认；
- [ ] 小程序备案、主体认证和类目通过；
- [ ] DCloud 账号实名认证；
- [ ] production uniCloud 套餐、余额告警和成员权限完成；
- [ ] 服务号和微信支付商户权限完成；
- [ ] H5/JSAPI/退款/出款能力完成。

### 域名

- [ ] 客户域、后台域、API 域备案并启用 HTTPS；
- [ ] uniCloud 自定义域名和 Web 安全域名完成；
- [ ] 小程序联网域名和 web-view 业务域名完成；
- [ ] 公众号授权域名和 JS 安全域名完成；
- [ ] 微信支付 H5 域名、JSAPI 目录和回调完成。

### 代码安全

- [ ] 本文 P0-01～P0-11 全部关闭；
- [ ] 密码改用慢哈希，后台启用 MFA；
- [ ] 系统任务不再允许普通客户端触发；
- [ ] 敏感字段和身份证真实加密；
- [ ] 多品牌商户 Secret 不串用；
- [ ] 客服链接路由正确；
- [ ] 隐私、协议、注销和个人信息权利可用；
- [ ] Secret 扫描和依赖安全检查通过。

### 资金

- [ ] 支付、重复回调、错误金额和主动查单通过；
- [ ] 退款、回调和退款查询补偿通过；
- [ ] 提现采用已确认的合规人工/自动出款方案；
- [ ] 微信账单、订单、支付、退款、佣金和钱包日终对平；
- [ ] 财务双人复核和大额审批完成；
- [ ] 真实备份和恢复演练完成。

### 运营

- [ ] 接单人员准入和协议完成；
- [ ] 客服、退款、异议和投诉 SLA 完成；
- [ ] 未成年人和内容安全规则完成；
- [ ] 风控、黑名单和禁止服务清单完成；
- [ ] 告警真实送达并有值班人；
- [ ] staging 真实验收证据完整；
- [ ] 回滚演练成功。

只要任一资金一致性、品牌隔离、敏感信息保护或真实备份项未通过，结论都应为 No-Go。

## 11. 建议立即执行的下一批开发任务

建议不要先购买大量云资源后再改代码，按以下顺序推进：

1. 确定单主体还是多主体品牌模式；
2. 修复 H5 客服链接路径；
3. 修复支付配置键名并完成品牌 Secret 路由方案；
4. 关闭普通客户端对系统任务的调用；
5. 升级密码哈希和后台 MFA；
6. 实现手机号、微信号、实名信息和身份证附件的真实加密；
7. 补齐隐私政策、协议、注销和数据权利功能；
8. 完成真实备份、告警、主动查单和对账任务；
9. 明确并实现出款方式；
10. 建立 staging 空间，开始真实 uniCloud 和微信验收。

这十项完成后，项目才适合进入“小额、白名单、可随时回滚”的商业灰度阶段。
