# 提交订单后提示“订单不可支付”

本次从客户端调用参数中发现确定的遗漏：`createOrderFromH5` 带有 `h5Token`，随后调用 `getPaymentParams` 时，JSAPI 路径仅传订单 ID、支付类型和服务号 openid，MWEB 路径仅传订单 ID 和支付类型，两处都漏传了下单凭证。

阿里云 `game-service/lib/services.cjs` 的 `getPaymentParams` 首先验证 `h5Token || token`。缺少下单凭证会返回 `ORDER_NOT_PAYABLE` 和“订单不可支付”，此时尚未发起微信预支付请求。服务号 openid 或小程序登录会话不能替代 H5 下单 token。

已在 `code/apps/client/src/pages/h5-order/index.vue` 两条支付路径中补传 `h5Token: token.value`。首次下单与继续支付共用这两个函数，因此均覆盖。后端签名、有效期、订单状态与商品匹配校验保持有效。

## 发布与复核

重新发布 `code/apps/client/dist/build/h5` 的完整内容到客户 H5 站点，然后关闭旧下单页，再从小程序重新打开。此次修改只涉及 H5，不需要重新上传云函数或重新发布小程序。

此前支付参数失败时订单可能已经创建，页面继续使用原有幂等键重试，避免重复建单。如果旧订单已关闭或超时，需回到订单列表核对状态；不能将已关闭订单直接改为待支付。

本次修复不等于微信商户预支付已实测通过；发布后才能继续验证真实微信支付配置和返回结果。查看请求时只确认 payload 存在 h5Token，分享日志时遮蔽其值。
