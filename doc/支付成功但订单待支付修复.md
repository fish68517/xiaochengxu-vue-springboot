## 代码中确认的问题

1. `completePayment` 在数据库事务内调用 `where().update()`；uniCloud 事务要求使用 `doc` 单记录更新。支付回调和主动查单共用这段落库逻辑，均可能因此失败回滚。现改为事务内读取最新订单/支付单、校验后用 `doc` 更新，两张表与到账日志原子提交。
2. `/pay-notify` 即使处理失败也返回 HTTP 200，可能被微信视为通知成功而停止重试。现失败返回 HTTP 500 和 `FAIL`，成功才返回 200。
3. 主动查单完成后返回旧订单对象，云端独立快照仍可能显示待支付；现落库后重新读取订单。
4. 订单列表/详情返回页面时没有刷新；现 `onShow` 重新加载。增加订单详情“已付款？查询并同步支付结果”，查询不发起扣款。

上述是当前代码可确认的缺陷；这笔订单具体云端报错栈仍需通过部署后的日志或原云函数日志确认，不能仅凭本地检查断言回调已经送达。

依据：[uniCloud 事务限制](https://doc.dcloud.net.cn/uniCloud/cf-database.html#start-transaction)、[微信支付成功回调通知](https://pay.wechatpay.cn/doc/v3/merchant/4012791861)。
