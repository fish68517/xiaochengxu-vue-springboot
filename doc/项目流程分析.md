# 项目商品流程分析

> 分析时间：2026-09-11  
> 分析范围：管理后台商品管理、客户端商品展示、uniCloud 云函数调用和品牌隔离。  
> 本文只分析当前问题并给出可执行处理方案，不把本地代码检查等同于正式环境验收。

## 一、结论

当前问题不是“uniCloud 接口无法查看”，也不是“客户端没有微信登录”。

真正原因是商品和客户端所属品牌不一致：

- 管理后台中的“王者荣耀”商品显示为 `品牌 default`、状态 `ON`。
- 当前 H5 客户端解析到的品牌是 `demo-a`，品牌名称为“星河服务”。
- 客户端商品接口只返回“当前品牌 + 已上架”的商品，所以 `default` 品牌商品不会出现在 `demo-a` 客户端。
- `listProducts` 是公开接口，浏览商品不要求微信登录。微信登录失败不会阻止首页商品加载。
- 品牌配置中的“小程序 AppID”不是 uniCloud 接口地址，也不是品牌 ID；它用于把某个微信小程序渠道识别并绑定到对应品牌。

因此，当前页面显示 `0 项` 是品牌数据不匹配导致的正确过滤结果，不是客户端未登录导致的。

## 二、管理后台的商品来自哪个接口

### 2.1 实际调用链

管理后台商品页打开时执行：

```text
pages/products/index.vue
  → api.listManagedProducts({})
  → uniCloud.callFunction({ name: "game-service", data: ... })
  → game-service action = listManagedProducts
  → products 集合
```

对应代码：

- `code/apps/admin/src/pages/products/index.vue` 第 113～117 行：加载 `listManagedProducts`。
- `code/apps/admin/src/api.js` 第 88～100 行：生产环境通过 `uniCloud.callFunction` 调用云函数。
- `code/apps/admin/src/api.js` 第 255 行：管理商品列表 action 为 `listManagedProducts`。
- `code/uniCloud-tcb/cloudfunctions/game-service/lib/services.cjs` 第 702～707 行：读取 `products` 集合，并按管理员品牌权限过滤。

### 2.2 为什么浏览器里只看到 `/client`

生产 H5 使用 uniCloud Web SDK。SDK 会把所有云函数调用统一发送到：

```text
POST https://api.next.bspapp.com/client
```

这个地址是 uniCloud 的通用 RPC 网关，不是具体商品接口地址。因此在 Network 列表中不会直接出现：

```text
/api/products
/api/listManagedProducts
```

查看具体接口的方法：

1. 打开浏览器开发者工具的“网络/XHR”。
2. 点开 `POST https://api.next.bspapp.com/client`。
3. 查看“请求载荷/Payload”。
4. 展开 `params` 中的 JSON 字符串。
5. 查找：

```json
{
  "functionTarget": "game-service",
  "functionArgs": {
    "action": "listManagedProducts",
    "payload": {}
  }
}
```

6. 在“响应/Response”中查看 `data`，这里才是云函数返回的商品数组。

因此，接口是可以查看的，只是被 uniCloud SDK 包装在统一的 `/client` 请求中。

## 三、客户端商品展示逻辑

### 3.1 客户端启动流程

```text
打开 H5
  → getBrandConfig：解析当前品牌
  → H5 环境尝试微信会话，因没有 wx.login 自动跳过
  → 首页调用 listProducts
  → 云函数只查询 status=ON 的商品
  → 再按解析出的 brandId 精确过滤
  → 页面再次保留 status=ON 的商品并渲染
```

关键代码：

- `code/apps/client/src/App.vue` 第 6～19 行：先加载品牌，再尝试建立微信会话；会话失败只记录日志，不阻断页面。
- `code/apps/client/src/api.js` 第 173 行：首页调用公开 action `listProducts`。
- `code/uniCloud-tcb/cloudfunctions/game-service/lib/auth.cjs` 第 14～20 行：`listProducts`、`getProduct`、`getBrandConfig` 都属于公开 action，不要求登录 token。
- `code/uniCloud-tcb/cloudfunctions/game-service/lib/services.cjs` 第 686～691 行：只返回 `status=ON` 且 `product.brandId === 当前品牌` 的商品。
- `code/apps/client/src/pages/index/index.vue` 第 67 行：前端接收列表后再次过滤 `status === 'ON'`。

### 3.2 微信登录在这里起什么作用

微信登录主要用于建立客户身份以及后续受保护业务，例如：

- 获取绑定客户身份的 H5 下单 token；
- 查询“我的订单”；
- 提交订单、支付以及售后操作。

它不控制首页商品是否可见。所以“没有微信登录”不是本次商品不显示的原因。

## 四、为什么品牌配置需要小程序 AppID

### 4.1 先区分项目中的四个标识

当前项目里有几个名字相近但用途完全不同的标识：

| 标识 | 当前示例 | 用途 |
| --- | --- | --- |
| `brandId` | `demo-a` | 平台数据库内部的品牌主键；商品、订单、钱包等业务数据都靠它隔离 |
| `brandCode` | `demo-a` | 构建和请求使用的品牌短码；H5 可以用它明确选择品牌 |
| 微信小程序 AppID | `wx...` | 微信分配给某一个小程序的真实身份，用于识别请求来自哪个小程序 |
| DCloud/uni-app AppID | `__UNI__80260AB` | DCloud 应用标识，用于 uni-app 工程；它不是微信小程序 AppID |

这四个值不能互相替代。特别是：

```text
demo-a              是平台品牌
wx...                是微信小程序
__UNI__80260AB       是 DCloud/uni-app 应用
```

### 4.2 AppID 在多品牌系统中的作用

这个项目是一套代码服务多个品牌。将来可能是：

```text
微信小程序 AppID-A → 星河服务（demo-a）→ 只显示 demo-a 商品
微信小程序 AppID-B → 青岚服务（demo-b）→ 只显示 demo-b 商品
```

小程序运行时，客户端可以通过 `wx.getAccountInfoSync()` 读取自己真实的微信 AppID，然后调用：

```text
getBrandConfig({ appId })
```

服务端在 `brands` 集合中查找绑定了该 AppID 的品牌，再返回该品牌的名称、主题、商品、客服信息等。这样同一套前端代码不用为每个客户复制一套项目。

对应代码：

- `code/apps/client/src/brand.js` 第 56～65 行：从微信运行环境读取小程序 AppID。
- `code/apps/client/src/brand.js` 第 81～100 行：使用 AppID/BrandCode 加载品牌。
- `code/packages/domain/src/brand-context.js` 第 12～25 行：根据 `brandCode` 或 `appId` 解析品牌，并拦截渠道错配。
- `code/uniCloud-tcb/cloudfunctions/game-service/lib/services.cjs` 第 2083～2093 行：保存品牌时要求 AppID 非空，并保证一个 AppID 不能绑定多个品牌。

所以，AppID 的核心作用是“微信渠道和平台品牌之间的绑定关系”，不是用来查询商品的普通接口参数。

### 4.3 H5 为什么也要求填写 AppID

纯 H5 浏览器中通常没有 `wx.getAccountInfoSync()`，当前线上 H5 实际发送的 `appId` 是空字符串。H5 当前依靠以下方式选择品牌：

1. 优先使用构建时的 `VITE_BRAND_CODE`；
2. 如果 BrandCode 也为空，则回落到 `isDefault=true` 的品牌。

因此，对于当前 H5 首页而言，小程序 AppID 并不是展示商品的必要条件。品牌表单仍强制填写，是因为当前数据模型把所有品牌都按“未来会对应一个微信小程序”设计，没有区分：

```text
H5_ONLY       仅 H5 品牌
MINI_PROGRAM  微信小程序品牌
```

这属于现阶段模型偏严格，而不是 uniCloud 的强制要求。后续可以工程化调整为：

- `H5_ONLY` 品牌：AppID 可为空，必须配置唯一 `brandCode` 或绑定域名；
- `MINI_PROGRAM` 品牌：AppID 必填，并校验微信登录凭据；
- 同时支持 H5 和小程序：BrandCode、AppID 都配置，并且必须指向同一个 `brandId`。

### 4.4 能否填写一个假的 demo 小程序 AppID

答案取决于要跑到哪一步。

| 目标 | 假的 demo AppID 是否可用 | 原因 |
| --- | --- | --- |
| H5 首页显示品牌和商品 | 可以，但没有必要 | H5 可以直接使用 `VITE_BRAND_CODE=demo-a`，不依赖微信登录 |
| 管理后台配置品牌和商品 | 可以作为临时占位值 | 当前后端只检查非空和唯一，不会向微信验证 AppID 所有权 |
| 微信开发者工具中只看静态页面/公开商品 | 可部分使用 | 不涉及客户身份时，公开接口仍可调用；但品牌 AppID 必须与运行渠道匹配或明确传 `brandCode` |
| 调用 `wx.login` 并建立真实客户会话 | 不可以 | 后端必须拿 AppID 和 AppSecret 调微信 `jscode2session` 换取真实 `openid` |
| “立即下单”完整客户流程 | 不可以只靠假 AppID | 商品详情点击下单会先执行 `ensureSession()`，必须完成真实 `wx.login` |
| 微信订阅消息、客服能力 | 不可以 | 需要真实小程序及对应权限、AppSecret 和模板配置 |
| 微信支付/退款 | 不可以 | 需要真实且合规的小程序/服务号、商户号及绑定关系 |
| 小程序正式发布 | 不可以 | 必须使用自己有权限的真实小程序 AppID |

当前云函数登录实现是明确的真实微信流程：

```text
wx.login 获取临时 code
  → game-service/miniLogin
  → WECHAT_MP_APPID + WECHAT_MP_SECRET
  → 微信 jscode2session
  → 获取 openid
  → 创建 CUSTOMER 会话
```

对应代码：

- `code/apps/client/src/api.js` 第 145～165 行：调用 `wx.login`。
- `code/apps/client/uniCloud-aliyun/cloudfunctions/game-service/lib/oauth.cjs` 第 36～45 行：使用 `WECHAT_MP_APPID`、`WECHAT_MP_SECRET` 调用微信 `jscode2session`，失败时不会降级为 Mock。
- `code/uniCloud-tcb/cloudfunctions/game-service/lib/services.cjs` 第 546～559 行：用微信返回的 openid 创建客户和会话。

假的 AppID 即使格式像 `wxdemo12345678`，也没有与之匹配的真实 AppSecret，微信不会返回 openid，所以无法跑通真实登录和下单链路。

### 4.5 当前最合适的演示方案

#### 方案一：只演示 H5 商品和管理流程

可以不申请新的小程序 AppID，也不需要伪造 AppID：

1. 保留现有品牌 `brandId=demo-a`。
2. 生产构建明确设置 `VITE_BRAND_CODE=demo-a`。
3. 将商品的 `brandId` 修正为 `demo-a`。
4. 通过 H5 演示品牌首页、商品列表和商品详情。

这可以解决当前“商品上架但客户端不显示”的问题。小程序 AppID 不是这个问题的关键。

#### 方案二：演示真实小程序登录和下单

不要手写一个虚构 AppID，应使用自己有权限的微信小程序 AppID，或者微信平台提供并且能够取得对应 AppSecret 的正式测试账号。以下配置必须保持一致：

```text
brands.demo-a.appId
apps/client/src/manifest.json 中 mp-weixin.appid
云函数环境变量 WECHAT_MP_APPID
云函数环境变量 WECHAT_MP_SECRET
客户端构建变量 VITE_BRAND_CODE=demo-a
```

其中 AppSecret 只能放在云端环境变量/密钥管理中，不能写进前端代码、Git 或文档。

当前工程已经在品牌初始化数据和 `manifest.json` 中写有一个 `wx...` AppID，但仅从代码无法证明该 AppID 是否属于当前使用者，也无法证明对应 AppSecret 已正确配置。必须到微信公众平台确认所有权；如果它不是自己的 AppID，就不能依赖它跑通微信登录。

#### 方案三：完全本地 Mock 演示

如果目前没有真实小程序账号，可以使用项目本地镜像 API 和演示数据跑后台业务流程，但这只能证明本地/Mock 逻辑，不代表微信登录、支付、订阅消息已经通过真实平台验收。

### 4.6 当前项目需要注意的单 AppID 限制

虽然品牌表支持多个品牌分别保存 AppID，但当前 `miniLogin` 使用的是云函数全局环境变量：

```text
WECHAT_MP_APPID
WECHAT_MP_SECRET
```

也就是说，现有实现更适合“一个云环境先服务一个真实小程序”。如果未来同一个云空间同时运行多个品牌小程序，需要进一步改造为：

1. 根据已解析的 `brandId` 选择对应 AppID；
2. 根据品牌的安全密钥引用读取对应 AppSecret；
3. 再调用 `jscode2session`；
4. 禁止前端直接提交或读取任何 AppSecret。

在该改造完成前，不应仅在品牌表里添加多个 AppID，就宣称多个小程序的真实登录都已打通。

### 4.7 对当前问题的直接建议

目前请不要为了让商品显示而随意修改小程序 AppID。当前最优先的操作仍然是：

```text
把“王者荣耀”商品 brandId 从 default 修正为 demo-a
并将 H5 生产构建 VITE_BRAND_CODE 固定为 demo-a
```

如果只看 H5，这两项完成后商品即可正常显示，不需要等待微信登录、AppID 和 AppSecret 的真实平台联调。

## 六、为什么商品被保存成了 default

当前管理后台顶部显示“全部品牌”，说明没有设置活动品牌：

```text
__admin_active_brand__ = 空
```

保存商品时：

1. `withActiveBrand()` 只有在活动品牌非空时才补充 `brandId`。
2. 商品表单本身没有品牌字段。
3. 后端 `saveProduct` 在缺少 `brandId` 时默认使用 `default`。

所以在“全部品牌”状态新增商品，会被静默保存成 `brandId=default`。

此外，管理概览页的品牌选择器使用了：

```vue
v-if="brandOptions.length > 2"
```

当前只有“全部授权品牌 + demo-a”两个选项，长度等于 2，因此选择器被隐藏，管理员无法在页面上切换到 `demo-a`。这是造成本次数据错位的直接 UI/流程缺陷。

## 十、最终判断

- uniCloud 运行正常，`/client` 是正常的统一云函数网关。
- 管理后台商品接口是 `game-service/listManagedProducts`。

## 十一、`assetIds=["demo-a"]` 为什么会提示商品素材不存在

### 11.1 `assetIds` 不是品牌 ID

本次请求中提交了：

```json
{
  "assetIds": ["demo-a"]
}
```

这里把“品牌 ID”和“商品素材附件 ID”混淆了。

| 字段 | 正确含义 | 当前示例 |
| --- | --- | --- |
| `brandId` | 商品归属的品牌 | `demo-a` |
| `assetIds` | `attachments` 数据集合中商品素材记录的 `_id` 数组 | 例如 `attachment-xxxx` |
| `images` | 商品图片 URL 数组 | 例如 `https://.../cover.jpg` |

`demo-a` 确实存在于 `brands` 集合，但后端处理 `assetIds` 时查询的是 `attachments` 集合：

```text
assetIds[0] = demo-a
  → 查询 attachments._id = demo-a
  → 没有找到附件记录
  → 返回“商品素材不存在或品牌不匹配”
```

对应代码位于 `code/uniCloud-tcb/cloudfunctions/game-service/lib/services.cjs` 第 1761～1764 行：后端逐个读取附件，并要求附件存在且附件的 `brandId` 与商品的 `brandId` 一致。

因此，品牌列表中存在 `demo-a` 不能证明 `attachments` 集合中存在 `_id=demo-a` 的素材记录。这是两张不同的数据表。

### 11.2 当前请求还没有修改商品所属品牌

本次请求 Payload 中没有：

```json
{
  "brandId": "demo-a"
}
```

虽然传入了 `assetIds=["demo-a"]`，但它不会被解释为品牌。当前后端在缺少 `brandId` 时仍回落到：

```text
brandId = default
```

所以即使把错误的附件 ID 清空，该商品仍然会保存为 `default` 品牌，客户端仍然不会显示。

### 11.3 当前商品没有素材时的正确请求

如果现在只是演示商品，不上传图片和附件，正确参数应为：

```json
{
  "id": "原商品ID",
  "brandId": "demo-a",
  "images": [],
  "assetIds": [],
  "status": "ON"
}
```

其他商品字段仍需完整提交。关键点是：

```text
品牌写入 brandId
素材附件写入 assetIds
没有素材就保持 assetIds=[]
```

### 11.4 有素材时的正确流程

如果以后需要上传商品素材，流程应为：

```text
先上传素材
  → 后端在 attachments 集合创建记录
  → 上传接口返回附件记录 _id
  → 把该 _id 放入商品 assetIds
  → 后端校验附件与商品同属 demo-a
  → 保存商品
```

不能把 `brandId`、文件名、图片地址或任意文字直接填进 `assetIds`。

### 11.5 本次需要实施的代码修复

为避免管理员再次混淆字段，需要进行以下增量修改：

1. 商品编辑表单增加明确的“所属品牌”选择器，提交字段为 `brandId`。
2. 将“品牌附件 ID”改名为“商品素材附件 ID”，补充说明“不是品牌 ID”。
3. 编辑现有商品时回显其 `brandId`；旧商品的品牌无效且系统只有一个启用品牌时，自动选择该品牌，允许管理员将 `default` 商品迁移到 `demo-a`。
4. 未选择有效品牌时禁止保存商品。
5. 后端保存商品前校验品牌真实存在且已启用。
6. 后端对附件错误分别提示“附件不存在”和“附件与商品品牌不匹配”，避免使用同一个模糊错误。
7. 管理概览只有一个正式品牌时也显示品牌选择器，避免始终停留在“全部品牌”。

完成后，当前商品应选择“星河服务（demo-a）”，并将错误的 `assetIds=demo-a` 删除；如果没有真实附件，素材附件 ID 保持为空。

### 11.6 请求中的 token 安全提示

uniCloud 请求 Payload 中包含管理会话 token。该 token 等价于短期登录凭证，不应粘贴到公开文档、群聊或截图中。发生泄露后应退出当前管理账号并重新登录，使旧会话失效；排查问题时只需要保留 action、业务 payload、错误 code 和 message。
