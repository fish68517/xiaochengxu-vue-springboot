# 下单提示“当前暂未开放灰度服务”

## 原因

页面已能读取商品并显示表单。本次提示来自阿里云 `game-service/lib/commercial-ops.cjs` 的 `enforceLaunchPolicy`，不是页面加载或微信登录失败。

旧逻辑只要 `APP_ENV=production` 就要求数据库 `configs` 中存在 `cfgKey=COMMERCIAL_LAUNCH_POLICY` 的策略，并且 `cfgValue.approved=true`、`paused=false`、品牌及用户均在白名单。缺配置、未批准、暂停、品牌不匹配或用户不匹配都返回同一句错误。截图只能确认触发了这条门禁，无法区分云数据库里的具体条件。

## 本次修改

新增云函数环境变量 `COMMERCIAL_LAUNCH_MODE`，将生产环境与灰度范围分开：

| 值 | 行为 |
|---|---|
| `public` | 公开接单，不要求灰度白名单与灰度限额；已有策略的 `paused=true` 仍暂停服务 |
| `gray`（默认） | 继续要求批准、品牌与用户白名单，并执行单笔/当日灰度限额 |
| `closed` | 暂停接单和申请支付参数 |

该检查同时用于创建订单和申请支付参数。公开模式仍经过原有商品上架、品牌、订单 token、表单与支付业务校验。

## 当前需要执行

如果本平台现在准备公开接单，在阿里云 `game-service` 环境变量中设置：

```text
APP_ENV=production
COMMERCIAL_LAUNCH_MODE=public
```

然后上传部署当前 `code/apps/client/uniCloud-aliyun/cloudfunctions/game-service`。本次是后端修改，无需重新发布 H5 或微信小程序。不要通过把 `APP_ENV` 改成 development 来绕过生产检查。

如果返回 `LAUNCH_PAUSED`，说明数据库已有策略显式设置了 `cfgValue.paused=true`。确认恢复服务后将该字段改为 false；其他字段保留。此次没有自动修改云端环境变量或数据库。

若仍使用灰度模式，新错误码可区分：`LAUNCH_NOT_APPROVED`（未批准或缺策略）、`LAUNCH_BRAND_NOT_ALLOWED`（品牌不在范围）、`LAUNCH_USER_NOT_ALLOWED`（用户不在范围）。

本次仅修改阿里云目录，腾讯云目录不参与。
