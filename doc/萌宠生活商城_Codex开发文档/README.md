# 萌宠生活商城微信小程序

> 项目定位：以萌宠销售为核心，以活动抽奖、积分、优惠券和“我的萌宠”服务提升用户参与度、复访率与成交转化。  
> 前端：uni-app + Vue 3 + TypeScript + Pinia  
> 后端：Python 3.12 + FastAPI + SQLAlchemy 2 + MySQL 8  
> 管理后台：Vue 3 + Vite + Element Plus  
> 部署：腾讯云 + Nginx + Docker Compose

---

## 1. 项目目标

本项目不是“付费购买抽奖资格”的抽奖小程序，而是一个 **萌宠交易商城 + 活动抽奖 + 用户服务** 小程序。

核心收入来自：

- 萌宠商品销售；
- 萌宠用品销售；
- 套餐销售。

抽奖仅作为运营活动：

- 管理员后台创建抽奖活动；
- 系统向用户展示/发送活动通知；
- 用户主动报名；
- 活动页实时显示参与人数；
- 到预设开奖时间后由服务端开奖；
- 公布中奖名单；
- 中奖用户联系管理员获取领奖方式。

> **禁止实现：支付 1 元/5 元购买抽奖资格。**
> 支付只用于购买明确商品。

## 2. 当前产品分类

商城一级分类：

1. **爬宠**
   - 乌龟
   - 小兔
2. **用品**
   - 龟粮
   - 兔粮
   - 饲养箱
   - 饮水器
   - 清洁用品
   - 环境用品
3. **套餐**
   - 新手饲养套餐
   - 乌龟入门套餐
   - 小兔入门套餐

> 注意：“乌龟 + 小兔统一归类为爬宠”是当前产品 UI/业务分类要求，开发时按该产品分类实现，不自行拆成“乌龟/兔子”两个一级 Tab。

## 3. 7 个核心页面

| 编号 | 页面 | 主要目标 |
|---|---|---|
| 1 | 首页 | 品牌展示、活动通知、精选商品、快捷入口 |
| 2 | 萌宠商城 | 浏览爬宠/用品/套餐并进入商品详情 |
| 3 | 萌宠详情 | 查看图片、档案、价格、咨询、购买 |
| 4 | 抽奖活动页 | 查看活动规则、报名、参与人数、倒计时 |
| 5 | 抽奖结果页 | 查看开奖状态、中奖名单、本人结果、领奖说明 |
| 6 | 下单支付 | 地址、商品、优惠券、金额确认、微信支付 |
| 7 | 我的萌宠 | 用户资产、订单、活动、已购买萌宠、饲养服务 |

## 4. 两条核心业务链路

### 4.1 商城购买链路

```text
首页
→ 萌宠商城
→ 萌宠详情
→ 立即购买 / 加入购物车
→ 确认订单
→ 微信支付
→ 支付结果
→ 我的订单
→ 我的萌宠
```

### 4.2 抽奖活动链路

```text
管理员后台创建抽奖活动
→ 发布活动
→ 首页/消息中心出现活动通知
→ 用户进入抽奖活动页
→ 查看规则/奖品/开奖时间/当前人数
→ 点击“立即报名参加”
→ 报名成功
→ 持续查看参与人数和开奖倒计时
→ 到达开奖时间
→ 服务端生成开奖结果
→ 抽奖结果页公开中奖名单
→ 用户查看本人是否中奖
→ 中奖用户联系管理员
→ 管理员告知领奖方式
→ 后台登记领奖状态
```

## 5. 开发原则

- UI 优先还原当前设计稿的暖橙色、奶油白、圆角卡片、治愈萌宠视觉。
- 所有金额、库存、优惠、开奖结果均以后端数据为准。
- 抽奖结果只能由后端生成，前端不得自行随机。
- 报名接口必须幂等，同一用户同一活动只能报名一次。
- 开奖必须由服务端任务触发，不依赖用户打开页面。
- 活动状态至少包含：`DRAFT`、`PUBLISHED`、`REGISTERING`、`WAITING_DRAW`、`DRAWING`、`DRAWN`、`CLOSED`。
- 支付成功以微信支付回调/主动查单为准，不能只依赖客户端 `requestPayment.success`。
- 不在前端保存微信支付密钥、数据库密码、管理员凭据。
- UI 中的参与人数、库存、订单状态必须支持加载态、空态、错误态。
