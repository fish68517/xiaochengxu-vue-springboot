# 小程序原生支付最小改造

## 当前流程

立即下单 → 原有 WebView 联系信息表单 → 创建待支付订单 → 同一个小程序原生支付页 → 微信收银台 → 服务端查单或支付通知确认结果。

保留原表单、商品和订单逻辑；不再在小程序 WebView 内进行服务号网页授权或调用网页 JSAPI 支付。订单详情的“继续支付”也进入原生支付页。

## 已完成的代码

- 新增 `code/apps/client/src/pages/order/pay.vue`，处理付款、取消、重试、查单及查看订单。
- H5 通过官方 JS-SDK 的 `wx.miniProgram.redirectTo` 返回本小程序；只传订单 ID，不传金额、OpenID、登录 token 或支付签名。
- 新增 `getMiniPaymentParams` / `getMiniPaymentStatus`，要求 CUSTOMER 登录会话，校验订单归属、品牌、金额和状态。
- 支付身份使用云端 `WECHAT_MP_APPID` 及小程序登录 OpenID。原生支付单使用固定订单级幂等标识；支付结果以后端验签回调或主动查单为准。
- 支付配置支持同一商户受控 AppID 列表，通知仍严格校验商户、AppID、金额和原生支付付款人。
- WebView 跳转失败保留已创建订单；不会因点击重试再次建单。新下单 token 会清理旧的页面幂等键。
- 不修改 `uniCloud-tcb`，也不修改现有商户私钥、APIv3 密钥等凭证。

## 发布顺序（需要三个部分一起更新）

1. 先上传阿里云 `code/apps/client/uniCloud-aliyun/database/payments.schema.json`（新增 `WECHAT_MINIPROGRAM` 渠道枚举，不清空数据），再上传 `code/apps/client/uniCloud-aliyun/cloudfunctions/game-service`，包含新增的 `lib/mini-payment.cjs` 和已忽略的 `private-config` 目录。
2. 发布 `code/apps/client/dist/build/h5` 到现有客户端 H5 站点根目录。只重新编译小程序不能更新远端表单。
3. 微信开发者工具重新导入/编译 `code/apps/client/dist/build/mp-weixin`，上传新体验版；退出旧版后重新扫码。

本地构建命令：在 `code/apps/client` 执行 `npm run build:prod` 和 `npm run build:mp-weixin`。

## 旧订单与验收

已经生成网页支付流水的旧订单不直接切换到原生支付，避免同一商户订单号混用两套 AppID。先查询是否已支付；未付旧订单等待关闭后新下单测试。不要删除支付流水或强改成已支付。

本地已通过 H5、小程序生产构建及针对支付身份、归属、幂等、查单和签名回调的回归检查；这不代表已部署或真实扣款验收通过。需真机验证：新建小额订单 → 拉起收银台 → 取消后继续支付 → 后端确认到账 → 我的订单状态更新。不得仅凭前端支付回调宣布到账。
