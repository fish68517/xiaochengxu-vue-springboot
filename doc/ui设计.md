## 1. 结论与设计原则

当前问题不是单纯“颜色不好看”，而是存在三个必须先解决的工程问题：

1. 三个 H5 入口的 `index.html` 均缺少移动端 `viewport`，这是客户 H5 在手机上整体缩小、文字和控件难以阅读的直接原因之一。
2. 客户端主动使用 `placeholder-image.svg`（白底红叉）作为底部导航、头像和功能入口图标；商品和品牌没有正式图片时又显示灰块，因此页面天然不具备演示条件。
3. 工作台和管理后台主要使用 `rpx` 编写桌面布局。在 1366/1440/1920 宽屏上，字号、间距和按钮偏小，同时每个页面各自维护导航，缺少标准的桌面端应用框架。

本轮 UI 落地必须遵守以下原则：

- **增量改造，不推倒重来**：保留现有 API、状态机、页面路径、角色权限、多品牌配置和业务方法，只重构展示层与少量展示数据适配。
- **先解决阻断演示的问题**：移动端缩放、红叉图标、灰色占位图、原始英文枚举、毫秒时间戳、巨大空白、桌面字号过小均为 P0。
- **三端统一品牌、区分场景**：客户端突出服务可信与购买转化；工作台突出订单处理效率；管理后台突出数据密度、权限和安全操作。
- **组件和令牌驱动**：颜色、字号、间距、圆角、阴影、状态色不能继续散落在页面中。
- **不以截图代替验收**：必须在真实手机宽度、主流桌面分辨率上检查可读性、交互、空态、异常态和滚动行为。

## 2. 现状审计

### 2.1 客户 H5

现有路由：

- `/pages/index/index`
- `/pages/category/index`
- `/pages/product/detail`
- `/pages/order/list`
- `/pages/order/detail`
- `/pages/order/webview-shell`
- `/pages/h5-order/index`
- `/pages/mine/index`

从手机截图和源码可确认的问题：

| 级别 | 现象 | 代码依据 | 影响 |
|---|---|---|---|
| P0 | 手机页面像桌面页缩小，字号和点击区很小 | `code/apps/client/index.html` 缺少 `meta viewport` | 手机无法正常演示和操作 |
| P0 | 底部导航、头像、功能入口显示红叉 | `client-tabbar.vue`、`mine/index.vue` 固定引用 `placeholder-image.svg` | 用户会认为资源加载失败 |
| P0 | 商品图片显示灰块或空白 | 商品图片依赖接口品牌资产，缺图时无演示级兜底 | 页面缺少视觉主体 |
| P0 | 底部导航语义错位 | 组件键是 `category`，文案来自 `tabLabels[1] = 订单`，点击却进入分类页 | 导航认知和实际页面不一致 |
| P1 | 首页仅有头部、搜索、筛选和商品，内容层级单薄 | `pages/index/index.vue` | 缺少首页氛围、信任和转化信息 |
| P1 | 分类页只有横向标签和单列商品 | `pages/category/index.vue` | 商品少时产生大面积空白 |
| P1 | “我的”页面信息不足 | `pages/mine/index.vue` | 不像完整个人中心 |
| P1 | 英文枚举直接展示，如 `companion`、`lol` | 多个详情、订单和工作台页面 | 对客户不友好 |
| P1 | 加载态只有文字“加载中…” | 客户端多个页面 | 页面跳变明显，缺少完成度 |

`code/apps/client/src/static/reference-assets` 已存在首页 Banner、商品图、头像、功能图标等参考素材，但目前页面并未形成统一的演示资产映射。该目录的 README 也明确这些是参考裁切图，不应直接视作正式商用素材。实施时可将其用于本地演示，但要与正式品牌素材目录和接口字段清晰区分。

### 2.2 客服/接单工作台

正式业务路由分为两组：

- 客服：`cs/workbench`、`cs/orders`、`cs/order-detail`、`cs/pool`、`cs/approvals`
- 接单人员：`worker/hall`、`worker/orders`、`worker/wallet`、`worker/profile`

`hall/index`、`orders/index`、`wallet/index`、`cs-orders/index` 是兼容跳转页，应继续保留，不重复设计业务页面。

当前问题：

- 全黑背景加青色发光边框，视觉更像开发调试工具，不像可长期使用的业务工作台。
- 1440×900 下内容几乎横向铺满，单个订单卡片过宽，信息扫读路径很长。
- 所有页面重复实现顶部导航，没有统一 Logo、角色、品牌、消息、退出和主内容宽度。
- 订单字段以一行斜杠连接，日期可能直接显示毫秒值，英文服务类型未转换。
- 主操作“抢单”横跨整张卡片，优先级过强；危险操作和普通操作样式区分不足。
- `rpx` 用于桌面字号与间距，导致 1440/1920 屏幕上视觉偏小。
- 客服和接单人员共享登录页，但当前切换器、错误提示、首次改密提示没有完整的交互层级。

### 2.3 管理后台

现有模块完整，包含概览、账号、商品、审核、订单、佣金账本、提现、异议、权限、审计、品牌、字典、配置、VIP、钱包和报表。问题主要集中在展示层：

- 没有桌面后台常见的左侧导航、顶部工具栏和面包屑，各页面像孤立表单。
- 深色高亮和全屏描边过多，列表、表单、弹层之间缺少层级。
- 1920×1080 下表格只占顶部很薄一条，字号过小，主体区域大量闲置。
- 订单、审计等模块把 API 字段和值直接展示，缺少格式化、脱敏、复制、溢出省略与字段解释。
- 高风险操作虽然已有 `DangerConfirm.vue`，但普通、次要、危险、不可用四种按钮语义尚未统一。
- `AsyncState`、`MoneyText`、`OrderStatusTag` 等已有组件应保留并升级，不另起一套。

## 3. 目标体验和视觉方向

产品关键词：**可信赖、清晰、专业、有活力、不过度游戏化**。

### 3.1 客户端

- 浅色背景、白色卡片、品牌主色强调，首屏必须出现品牌、搜索/分类、服务推荐和信任信息。
- 图片承担主要视觉表达，文案简短明确；价格与“立即下单”是最高层级。
- 多品牌只改变 Logo、主色、辅助色、Banner 和运营文案，不改变信息架构。
- H5 与微信小程序使用相同内容层级；仅安全区、客服能力和下单跳转方式按平台适配。

### 3.2 工作台

- 使用“浅色工作区 + 深色窄侧栏 + 品牌色操作”的专业运营界面。
- 订单不是铺满全屏的大卡片，而是在限定宽度内呈现可扫读字段，主操作靠右。
- 客服侧重待办、筛选、录入、指派、审批；接单人员侧重订单池、当前任务、收益和资料状态。
- 在 390px 手机上可完成接单核心操作；复杂客服录入建议平板或桌面。

### 3.3 管理后台

- 标准 B2B 管理台：固定侧栏、顶部栏、内容容器、页面标题、筛选栏、数据表格、右侧详情抽屉。
- 默认浅色，提高长时间阅读舒适度；危险动作使用红色且必须二次确认。
- 1440×900 为主设计画布，1366×768 必须无布局截断，1920×1080 不得无限拉宽。

## 4. 设计令牌

三端统一采用语义令牌。客户端保留现有 `--brand-*` 入口，并扩展为完整令牌；工作台和管理台逐步停止页面直接引用 `--es-*`。

  --color-primary-hover: #4850df;
  --color-primary-soft: #eef0ff;
  --color-secondary: var(--brand-secondary, #7c3aed);

  /* 中性色：不允许品牌配置覆盖 */
  --color-page: #f5f7fb;
  --color-surface: #ffffff;
  --color-surface-raised: #ffffff;
  --color-text: #101828;
  --color-text-secondary: #475467;
  --color-text-tertiary: #98a2b3;
  --color-border: #e4e7ec;
  --color-divider: #eaecf0;

  /* 业务状态色：不允许品牌配置覆盖 */
  --color-success: #12b76a;
  --color-warning: #f79009;
  --color-danger: #f04438;
  --color-info: #2e90fa;

  --radius-xs: 6px;
  --radius-sm: 8px;
  --radius-md: 12px;
  --radius-lg: 16px;
  --radius-pill: 999px;

  --shadow-card: 0 1px 3px rgba(16, 24, 40, .08), 0 1px 2px rgba(16, 24, 40, .04);
  --shadow-popup: 0 12px 32px rgba(16, 24, 40, .16);
  --focus-ring: 0 0 0 3px rgba(91, 99, 246, .18);

### 4.1 字体

字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。不依赖远程字体，保证局域网演示和小程序环境稳定。

| 场景 | 客户端 | 工作台/管理台 |
|---|---:|---:|
| 页面主标题 | 22px / 700 | 24px / 600 |
| 卡片标题 | 17px / 600 | 16px / 600 |
| 正文 | 15px / 400 | 14px / 400 |
| 辅助文字 | 13px / 400 | 13px / 400 |
| 表格 | 不使用 | 14px / 400 |
| 金额/关键数字 | 24–32px / 700 | 24–28px / 600 |

客户端页面可继续使用 `rpx` 适配小程序，但按 750 设计稿换算后正文不得低于约 28rpx。工作台和管理后台的桌面样式统一改为 `px`/`rem`，不要继续以 `rpx` 作为桌面主单位。

### 4.2 间距与尺寸

- 基础间距：4、8、12、16、20、24、32、40、48px。
- 客户端左右安全边距：16px；卡片间距：12px；模块间距：20–24px。
- 桌面内容区最大宽度：工作台 1280px，管理后台 1440px；超宽屏居中，不无限拉伸。
- 客户端主按钮高 48px，普通控件高 44px；桌面输入框和按钮高 36–40px。
- 所有触摸目标不小于 44×44px；纯图标桌面按钮不小于 32×32px。

## 5. 响应式与 H5 基础修复

### 5.1 三个入口必须补齐 viewport

`code/apps/client/index.html`、`code/apps/workbench/index.html`、`code/apps/admin/index.html` 的 `<head>` 均增加：

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />
<meta name="theme-color" content="#ffffff" />
```

同时在三端全局样式增加：

```scss
html, body, #app { min-height: 100%; }
body { margin: 0; -webkit-font-smoothing: antialiased; }
*, *::before, *::after { box-sizing: border-box; }
button, input, textarea { font: inherit; }
```

不要通过浏览器缩放或在页面根元素设置固定 `transform: scale()` 修复；这会继续破坏点击坐标、弹层和安全区。

### 5.2 断点

| 断点 | 客户端 | 工作台 | 管理后台 |
|---|---|---|---|
| `< 480px` | 单手机视图，2 列商品卡 | 侧栏变底部/抽屉导航，订单单列 | 仅保证登录、只读和紧急审批；表格转卡片/横滚 |
| `480–767px` | 最大 480px 居中 | 单列卡片、顶部工具栏 | 筛选折叠，表格横向滚动 |
| `768–1023px` | 居中预览壳 | 64px 图标侧栏 | 72px 图标侧栏，抽屉宽 70vw |
| `1024–1439px` | 居中预览壳 | 220px 侧栏 | 224px 侧栏，内容自适应 |
| `≥ 1440px` | 480px 居中预览壳 | 内容最大 1280px | 内容最大 1440px |

客户端桌面访问时可显示浅灰背景和 480px 的居中手机画布，但在真实手机上必须占满 CSS 视口宽度，不能再出现“半屏缩小”。

### 5.3 安全区与高度

- 底部固定操作使用 `padding-bottom: max(12px, env(safe-area-inset-bottom))`。
- 页面最低高度使用 `100dvh`，兼容回退为 `100vh`，避免手机浏览器地址栏伸缩产生跳动。
- 客户端底栏建议内容高 56px，加安全区后自动增高；页面底部预留同等空间。
- 弹层最大高度用 `calc(100dvh - 32px)`，内部滚动，背景禁止滚动穿透。

## 6. 客户 H5 页面设计

### 6.1 全局框架

```text
┌──────────────────────────────┐
│ Logo  品牌名           客服  │  56px，吸顶
├──────────────────────────────┤
│ Banner / 主活动              │  16:7，圆角 16px
│ 搜索框                       │
│ 分类图标：热门/陪玩/套餐...  │
│ 安心服务：明码标价·全程跟进  │
│ 推荐服务                     │
│ ┌────────┐ ┌────────┐       │
│ │ 商品卡 │ │ 商品卡 │       │
│ └────────┘ └────────┘       │
├──────────────────────────────┤
│  首页       订单       我的  │  56px + safe-area
└──────────────────────────────┘
```

底部导航最终固定为“首页、订单、我的”。当前 `category` 键实际跳分类页但显示“订单”，必须统一：

- 首页：`/pages/index/index`
- 订单：`/pages/order/list`
- 我的：`/pages/mine/index`
- 分类筛选保留在首页，`/pages/category/index` 作为“全部分类/搜索结果”二级页，不占底部 Tab。

如果必须保留分类为 Tab，则文案应改成“分类”，订单从“我的”进入；两种方案不能混用。推荐前三项方案，因为订单是客户下单后的高频入口。

### 6.2 首页 `/pages/index/index`

首屏顺序：

1. 56px 自定义品牌头部：Logo + 品牌名称；右侧客服使用本地图标和文字，不只显示小药丸。
2. 运营 Banner：建议 750×320 或 1500×640，图片内避免放关键小字；加载失败使用品牌渐变底与文本兜底。
3. 搜索：44px 高，点击/输入后在当前页筛选或进入分类页；搜索图标禁止使用字符 `⌕`。
4. 分类入口：4–5 个图标宫格；来源为商品的游戏、服务类型或后台配置，不出现原始 `lol`。
5. 信任条：明码标价、客服跟进、进度可查，可点击查看服务规则。
6. 推荐服务：两列商品卡，展示封面、标题、服务类型、销量/已服务数量（有真实字段才显示）、价格。

商品卡规范：图片比例 4:3；标题最多两行；标签最多两个；价格左下；右下使用“去看看”箭头，不把整卡塞满文字。只有一个商品时，仍保持半宽卡或用“主推大卡 + 服务说明”填充内容，不将其拉伸成全屏横条。

### 6.3 分类页 `/pages/category/index`

- 顶部为返回、标题“全部服务”、搜索入口。
- 一级筛选横向吸顶；增加“综合 / 销量 / 价格”排序条。
- 手机下默认两列卡片；当标题、描述字段较长时允许切换为紧凑单列。
- 选中项使用品牌色浅底 + 深色文字，避免整片高饱和色。
- 无结果时展示本地空状态插图、说明和“清除筛选”，不能只留大块空白。

### 6.4 商品详情 `/pages/product/detail`

- 顶部主图 1:1 或 4:3，可轮播；加载失败使用带品牌 Logo 的默认服务图。
- 摘要区依次为标题、中文服务标签、保障说明、价格。
- 内容区分成“服务包含”“下单须知”“服务流程”“退款/售后规则”，使用折叠面板减少首屏长度。
- 底部固定栏：左侧客服，右侧 65% 宽主按钮“立即下单”。当前“立即下单”和“联系客服”上下各占一整行应合并。
- 下架、品牌停用、网络错误分别显示，不把全部异常统称“商品不存在”。

### 6.5 下单页 `/pages/h5-order/index`

- 顶部显示三步流程：填写信息 → 确认订单 → 支付结果。
- 商品摘要折叠为紧凑卡；动态表单字段按配置渲染，但统一标签、必填标记、说明、错误信息。
- 时间字段使用日期时间选择器，禁止要求用户输入毫秒值。
- 底部结算栏显示应付金额和主按钮；提交中禁止重复点击并显示进度。
- 成功页展示订单号、下一步说明、“查看订单”和“返回首页”。

### 6.6 订单列表与详情

## 8. 管理后台设计

### 8.1 应用框架与菜单

管理后台使用 `AdminShell`：左侧菜单 224px、顶部栏 64px、内容区最大 1440px。菜单按现有 `visibleMenus` 和角色权限动态生成，不在前端仅靠隐藏按钮代替后端鉴权。

建议菜单分组：

| 分组 | 页面 |
|---|---|
| 总览 | 管理概览 |
| 交易 | 订单管理、审核中心、异议仲裁 |
| 财务 | 佣金账本、提现审批、钱包管理、报表 |
| 服务供给 | 商品管理、账号管理、VIP 名单 |
| 多品牌 | 品牌配置、字典管理、配置管理 |
| 安全与权限 | 角色与品牌权限、审计日志 |

顶部栏包括：侧栏折叠、面包屑、当前品牌选择、用户角色、退出。品牌切换是全局上下文，切换后当前页面重新加载；无权限时不出现“全部品牌”。

### 8.2 登录 `/pages/login/index`

- 居中 420×自适应登录卡，背景使用低对比度品牌渐变/几何纹理，不使用青色霓虹描边。
- 显示系统名称、环境标签（仅开发/测试）、手机号、密码、登录按钮和错误区域。
- 连续失败、账号无权限、网络错误使用不同提示。
- 登录后按角色可见菜单跳转到第一个可访问页面，而不是假设所有人都能看 Dashboard。

### 8.3 Dashboard `/pages/dashboard/index`

布局：

1. 页面标题、时间范围、刷新和品牌范围。
2. 订单总数、待受理、服务中、接单人员四个统计卡；卡片显示与上一周期的变化时必须有真实数据，否则不展示伪趋势。
3. 左侧订单状态分布或近 7 日趋势，右侧待办队列。
4. 快捷入口只显示最常用 4–6 项，不把全部 14 个模块铺成宫格；完整功能由侧栏承载。

图表若当前接口没有时序数据，第一版先用状态分布条形图，不能在前端生成虚假经营数据。

### 8.4 列表页统一模板

适用于订单、账号、商品、审核、账本、提现、异议、权限、审计、VIP、钱包和报表：

```text
页面标题 + 说明                              主要操作
统计摘要（可选）
关键词  状态  日期  品牌  [更多筛选] [重置] [查询]
┌───────────────────────────────────────────────┐
│ 表头（吸顶）                                  │
│ 行数据                                  操作  │
│ 行数据                                  操作  │
└───────────────────────────────────────────────┘
已选择 N 项 / 批量操作                分页与每页数量
```

统一规则：

- 表头 44px、数据行最低 52px；奇偶行不必强对比，悬停时使用浅品牌色。
- 订单号、用户 ID、流水号等长文本单行省略，悬停显示全文并提供复制。
- 金额右对齐；时间统一格式；状态用浅底标签；操作最多直接显示两个，其余进入“更多”。
- 列表必须有加载骨架、空态、错误态、无权限态和分页态。
- 抽屉宽度：普通详情 560px，复杂订单/品牌配置 720–860px；1366 宽度下不超过 70vw。
- 删除、出款、退款、封禁、权限变更必须使用升级后的 `DangerConfirm`，确认框写明对象和后果。

### 8.5 重点模块

- **订单管理**：列表 + 右侧详情抽屉；状态时间线用中文动作，不展示裸 JSON；指派/改派保留历史。
- **商品管理**：列表与编辑抽屉分离；封面上传提供 4:3 裁切预览；动态字段配置有预览区。
- **品牌配置**：基础信息、主题、素材、文案、联系方式分 Tab；主题颜色实时预览，但发布前展示差异和版本号。
- **财务相关**：金额列右对齐、正负色区分、冻结金额有说明；出款凭证和操作人不可省略。
- **权限管理**：按“用户—角色—品牌范围”三段呈现；通配范围 `*` 在 UI 中显示“全部授权品牌”，同时给予高风险提示。
- **审计日志**：默认显示人类可读摘要；请求/响应 JSON 放详情折叠区并脱敏手机号、token、身份证等字段。
- **报表**：筛选、摘要指标、趋势图、明细表和 CSV 导出保持同一筛选条件；空数据不画零值伪趋势。

## 11. 交互和状态标准

每个异步页面至少实现以下状态：

| 状态 | 展示要求 |
|---|---|
| 首次加载 | 骨架屏，保持最终布局高度 |
| 局部刷新 | 原内容保留，刷新按钮转动/显示时间，不整页闪白 |
| 空数据 | 插图、原因、下一步操作，如“清除筛选” |
| 网络错误 | 简明原因、重试按钮；开发环境可展开技术详情 |
| 无权限 | 说明当前角色/品牌范围，提供返回可访问页面 |
| 禁用 | 按钮保留但降级，并显示不可执行原因 |
| 提交中 | 按钮锁定、防重复、明确进度 |
| 成功 | Toast + 页面数据刷新；关键资金动作显示结果摘要 |
| 高风险确认 | 对象、金额/权限、后果、确认与取消 |

全局 Toast 仅用于短反馈。字段校验错误必须显示在字段下方；系统级错误显示页面提示条；不可把所有错误都压成 Toast。

## 12. 可访问性与安全显示

- 正文与背景对比度目标不低于 4.5:1，大字号不低于 3:1。
- 键盘可完成登录、筛选、表格操作和弹层关闭；焦点样式可见。
- 图标按钮必须有可读名称；表单输入有明确 label，不能只靠 placeholder。
- 支持 `prefers-reduced-motion`；动画以 120–240ms 淡入/位移为主，不使用闪烁和持续发光。
- 手机号默认展示为 `138****0000`；身份证、微信、token、回调原文等敏感信息默认脱敏或折叠。
- 复制敏感数据和导出应保留现有审计能力；UI 改造不得绕过权限检查。

## 16. 完成定义（Definition of Done）

一个页面只有同时满足以下条件才算 UI 完成：

1. 使用语义设计令牌，不新增散落的主题硬编码。
2. 使用统一壳、标题、状态、按钮、表单或列表组件。
3. 真实数据、演示数据、空数据、异常数据均不破版。
4. 手机/桌面目标视口通过，且没有依赖浏览器缩放。
5. 图片有明确尺寸、压缩和失败兜底，无红叉或灰色临时块。
6. 英文枚举、时间、金额、手机号等完成格式化/脱敏。
7. 加载、错误、无权限和危险操作反馈完整。
8. 保留现有路由、权限和业务动作，相关自动化通过。
9. 截图进入 `TestEvidence/ui-baseline` 并由演示负责人确认。
