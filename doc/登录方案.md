# 客户端登录方案

## 一、为什么出现“会话已过期，请重新登录”

截图是“我的订单”页面加载失败，并非整个小程序无法打开，也不是提示微信账号退出登录。

结合当前源码，存在明确的会话恢复缺口：

1. 阿里云 `game-service/lib/auth.cjs` 为客户签发的业务 token 有效期为 **30 分钟**。验签时超过 `exp` 就抛出“会话已过期,请重新登录”。
2. 客户端 `src/api.js` 的 `ensureSession()` 只要发现本地有 token 就直接复用，没有检查有效期。缓存中的 `ts` 也没有参与有效期判断。
3. `pages/order/list.vue` 先调用 `ensureSession()`，再查询 `listMyOrders`；收到未授权错误后直接展示失败，没有重新建立会话。所以点击“重新加载”仍可能使用同一个过期 token。
4. 订单详情也存在同样缺口。下单桥接和原生支付页已有局部重新登录逻辑，但没有覆盖所有需要登录的页面。
5. `pages/mine/index.vue` 读取通用的 `user` 缓存，而实际客户会话保存在 `__client_session_v1__`；页面没有真正的登录按钮，登录提示与实际状态可能不一致。
6. `App.vue` 启动时已尝试静默登录，但同样受旧 token 直接复用影响。仅增加一次启动登录不能解决运行期间过期的问题。

**判断：截图与上述代码缺口高度一致。当前并未读取该手机本地缓存或线上当次完整调用日志，因此不能断言具体是哪一次 token 到期；但此缺口需要修复。** 本次问题不是全品牌商品展示导致的，也不能通过给客户添加全品牌权限解决。

## 二、微信已登录，不等于本项目已登录

需要区分三个层次：

- **微信客户端账号状态**：用户当前使用哪个微信账号。
- **微信小程序登录凭证**：通过 `wx.login()` 获取临时 code，由后端兑换 OpenID 等信息。
- **本项目业务会话**：后端根据微信身份签发的 token，用于查询本人订单、申请下单链接和原生支付。

因此，即使微信一直登录，本项目的 30 分钟 token 仍可能过期。正确处理是重新调用微信登录能力建立业务会话，不是要求用户输入微信密码或重新登录微信客户端。

`wx.checkSession()` 检查的是微信侧登录态，不能替代本项目 token 的有效期判断和后端验签。小程序静默身份登录也不代表已经获得手机号、头像、昵称等个人资料；不应为了查询订单强制收集这些资料。

参考：[DCloud 登录 API](https://uniapp.dcloud.net.cn/api/plugins/login.html)、[微信官方登录说明入口](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)、[微信官方 checkSession 入口](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/login/wx.checkSession.html)。本次微信官方网页未能直接抓取，微信 API 的具体上线适配还需开发者工具验证；项目自身会话结论来自本地源码。

## 三、方案对比与选择

| 方案 | 实际实现方式 | 优点 | 问题与建议 |
| --- | --- | --- | --- |
| 方案一：打开前必须登录 | 小程序进入后强制完成业务登录才显示内容，并不能借微信已登录直接获得业务 token | 所有业务页面统一处于已登录状态 | 登录服务异常会阻断商品浏览；仍需解决后续过期，不推荐全局强制 |
| 方案二：只在“我的”提供登录 | 用户点击个人中心“微信登录”建立业务会话 | 入口明确，失败可手动重试 | 单独加按钮不能解决订单页和支付过程中 token 过期，只适合作为兜底 |
| 推荐方案：公开浏览＋按需自动登录＋手动兜底 | 首页/商品免登录；订单、下单等需要身份时自动建立或恢复会话；个人中心提供入口 | 保留现有体验，减少手工操作，也有清晰的恢复入口 | 需要集中管理会话、区分错误类型，改造量可控 |

**推荐第三种方案，将方案二作为补充，不把方案一作为全局门槛。**

预期体验：

1. 打开小程序即可浏览全部启用品牌的上架商品。
2. 点击“订单”或当前支持渠道的“立即下单”，自动确保业务会话有效。
3. token 过期时，在后台重新获取一次微信 code、调用 `miniLogin`，再恢复允许重试的读取操作；正常情况下用户不需要手动操作。
4. 自动登录失败，显示“登录暂未完成”及“微信登录 / 重新登录”按钮；仍允许返回首页浏览。
5. “我的”清晰显示“未登录、登录中、已登录、需要重新登录”等状态，并提供同一个登录入口。

普通 H5 浏览器不能直接使用小程序 `wx.login`，不应显示一个注定失败的小程序登录按钮；显示“请在微信小程序中查看我的订单”。服务号网页授权与小程序身份不同，不在本次方案中强行合并。

## 四、可落地的代码任务

### 阶段一：修复过期后反复失败

**1. 后端明确会话错误与到期时间**

- 修改阿里云 `game-service/lib/auth.cjs`：针对缺失、过期、签名无效分别返回稳定业务码，例如 `SESSION_MISSING`、`SESSION_EXPIRED`、`SESSION_INVALID`。
- 修改 `game-service/index.js`：仅保留这些明确的会话错误码及现有 `ROLE_FORBIDDEN`，不要把所有认证异常一律映射为可恢复的过期错误。
- `miniLogin` 增加 `expiresAt`、`serverTime` 等返回字段，使用同一次签发得到的到期时间，不在前端另写一份固定 TTL；保留当前字段兼容旧客户端。
- 本次不延长全局 token 到期时间、不取消验签，也不改变管理员/客服/工作人员的权限或 MFA 策略。

**2. 客户端集中管理业务会话**

- 在 `src/api.js` 配套独立的客户会话模块：统一读取、保存、失效清理和响应式状态。
- 保存 `token/customerId/brandId/expiresAt` 及当前小程序 AppID、启动品牌 Code；上下文不符的缓存不复用。全品牌目录中的商品选择不能改写登录渠道或客户品牌权限。
- 对无到期时间的历史缓存执行一次重新登录迁移，不继续无限复用。
- `ensureSession()` 检查到期信息，可在到期前约 60 秒按需更新；后端验签始终是最终依据，前端时间判断只是减少失败请求。
- 用共享的进行中 Promise 合并并发登录：App、订单页同时触发时只进行一次登录；每次登录使用新 code，不重复兑换旧 code。
- 登录失败清理该次失效缓存并结束 loading，提供重试，不允许无限循环。旧请求失败不能清除刚建立的新会话，退出或身份切换后不能用迟到响应恢复旧状态。

**3. 恢复策略按接口分类**

- 为 `listMyOrders`、`getMyOrder`、`getMiniPaymentStatus` 等明确只读接口增加统一会话保障。
- 仅在明确的会话过期/缺失/失效情况下，重新登录一次，并且只重发一次原读取请求；新请求必须携带新 token。
- 品牌越权、角色不足、账号不可用、商品下架等业务错误不触发自动重新登录。旧版 `UNAUTHORIZED` 仅作窄范围兼容，不能无条件反复登录。
- 现有 `getH5OrderToken` 和原生支付页的局部处理统一接入同一会话模块，避免多处重复刷新。
- 下单、支付、提交凭证、提交异议等写操作不做通用自动重放；先确保会话有效。确需重试时，必须证明鉴权失败发生在业务执行前，并保留原幂等键。网络超时、支付结果未知时先查询结果，不重复下单或扣款。
- H5 下单桥接 token 与小程序业务 token 分开处理，不通过小程序重新登录悄悄替换 H5 订单关联。

### 阶段二：补齐“我的”和失败恢复界面

- `pages/mine/index.vue` 改为读取统一客户会话，不再使用通用 `user` 缓存；页面再次显示时同步状态，不能用非响应式缓存读取长期显示“已登录”。
- 增加“微信登录 / 重新登录”按钮，调用阶段一的同一登录方法，防止连点；成功后更新状态，并返回原订单操作或刷新当前页面。
- 已登录显示“微信用户”或系统已有的客户资料；不虚构微信昵称、头像、手机号，不显示完整 OpenID/token。
- 订单列表和详情区分“登录失败”和“订单查询失败”：登录问题按钮执行登录恢复，不再只是重新发送旧请求；普通网络故障仍提供“重新加载”。
- 保留“去逛逛”、客服入口；不把鉴权失败渲染成“暂无订单”，避免用户误以为历史订单丢失。
- `App.vue` 不将登录作为公开浏览的前置条件。可保留非阻塞的会话准备，但不得出现静默登录失败就阻断首页的行为；如添加“退出登录”，需禁止自动登录立刻把用户重新登录，且说明本地退出不等于撤销已签发 token。
- 遵循已配置的隐私告知流程；基础身份登录和手机号、头像等资料授权分开设计，不顺带新增资料采集或手机号强制绑定。

## 五、排查日志与验收标准

日志只记录阶段、接口名、错误码、刷新次数和请求关联 ID，不记录 token、code、session_key、OpenID、手机号或密钥全文。

验收场景：

- 首次打开可浏览商品；进入订单页可建立会话。
- 放置超过 30 分钟后再次打开订单页，可自动恢复，不要求退出微信。
- 连续点击重试或多个页面同时请求，只触发一次并发登录，不出现刷新风暴。
- 手动登录成功后，“我的”与订单页状态一致；失败时有明确入口且没有永久加载动画。
- token 过期、网络断开、品牌越权分别走不同提示；品牌越权不自动扩大客户权限。
- 恢复登录后只查看原客户身份下的订单；更换微信身份后不显示上一身份的缓存订单。
- 支付中遇到过期或超时不重复创建订单、不自动重复拉起扣款；仍以服务器支付结果为准。
- 普通 H5 不调用小程序登录；管理员、客服和工作人员会话不受本次改造影响。
